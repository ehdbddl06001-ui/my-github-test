### (PAPER.md §10의 상세 계획)

**작성 기준일**: 2026-07-27

## 1. 왜 대규모 DB인가 — 검정력이 유일한 이유

PAPER.md §5.3의 결론: MIT-BIH DS2에서 S를 가진 환자는 **16명**, 환자별 F1의
σ ≈ 0.32 → 평균의 95% 신뢰구간 **±0.16**.

우리가 시도한 개선들의 효과 크기는 0.01~0.07이었다. **측정계가 분해할 수 없는 양을
쫓고 있었다.** 환자 수를 늘리는 것 외에 이 한계를 푸는 방법은 없다.

### 1.1 환자 수 대비 검출 가능 효과 (σ=0.32 가정)
| 환자 수 N | SEM = σ/√N | 95% CI 반폭 | 검출 가능한 최소 개선 |
|---|---|---|---|
| **16 (현재 MIT-BIH DS2)** | 0.080 | **±0.157** | 0.16 — 사실상 불가 |
| 32 (INCART, 보유) | 0.057 | ±0.111 | 0.11 |
| **78 (MIT-BIH SVDB)** | 0.036 | **±0.071** | 0.07 |
| 300 | 0.018 | ±0.036 | 0.04 |
| **1,000** | 0.010 | **±0.020** | **0.02** ← 우리가 쫓던 크기 |

> **결론**: 최소 수백 명 규모에서만 우리가 관찰한 크기(0.02~0.07)의 개선을 통계적으로
> 주장할 수 있다. 이것이 대규모 DB로 가는 유일하고 충분한 근거다.

## 2. 후보 데이터베이스 비교

| DB | 환자/레코드 | 리드 | 샘플링 | 비트 라벨 | S 풍부도 | 우리 파이프라인 적합성 |
|---|---|---|---|---|---|---|
| **MIT-BIH SVDB** (Supraventricular Arrhythmia DB) | 78 레코드 | **2** | 128 Hz | ✅ AAMI 매핑 가능 | **★S 보강 목적으로 제작** | **매우 높음** (같은 계열·2리드) |
| **INCART** (보유) | 75 레코드 / **32 환자** | 12→2 선택 | 257 Hz | ✅ | 중간(S 1.12%) | 높음(이미 전처리 완료) |
| **Icentia11k** | **11,000 환자** | **1** (단일) | 250 Hz | ✅ 20억 비트 | 높음(다양) | 중간 — **단일리드 구조 변경 필요** |
| MIT-BIH LTDB | 7 | 2 | 128 Hz | ✅ | 낮음 | 낮음(환자 수) |
| PTB-XL | 18,885 환자 | 12 | 500 Hz | ❌ **10초 진단 라벨**(비트 아님) | — | **부적합**(비트 라벨 없음) |
| Chapman-Shaoxing | 10,646 환자 | 12 | 500 Hz | ❌ 리듬 라벨 | — | 부적합 |

### 2.1 선정 및 순서 (권장)
```
Phase A: MIT-BIH SVDB (78레코드, 2리드)   ← 즉시. 최소 변경, 최대 정보
Phase B: INCART 재실행 (32환자)           ← L1–L5 수정 후. 이미 보유
Phase C: Icentia11k (수백~수천 환자)      ← 단일리드 대응 후. 본 게임
```

**왜 SVDB부터인가**
1. **2리드·AAMI**로 우리 파이프라인이 거의 그대로 동작(리샘플 128→360Hz만).
2. **S 보강을 목적으로 만들어진 DB** — S를 가진 환자가 16명 → 수십 명으로 증가.
3. 검정력 ±0.157 → **±0.071**로 2배 이상 개선. 우리가 관찰한 0.07 크기 효과가
   비로소 검정 가능해진다.
4. MIT-BIH와 같은 기관·같은 주석 규약 → 도메인 shift 교란이 최소.

**왜 Icentia11k가 최종 목표인가**
- 환자 1,000명만 써도 검출 한계 **±0.02**. 우리가 쫓던 모든 효과가 검정 가능.
- 단, **단일리드**라 구조 변경 필요(§4.2).

## 3. 선결 조건 — 지금 코드로 바로 가면 안 되는 것들

PAPER.md §6.5의 L1–L5를 먼저 고쳐야 한다. **이 수정 없이 얻은 교차DB 수치는
방법의 성능이 아니라 전처리 비대칭을 측정한다.**

| # | 수정 | 내용 | 난이도 |
|---|---|---|---|
| **F1** | **R피크 재정합** | 주석 위치에서 ±50ms 창의 `argmax(|VM|)`로 R 재탐색 후 세그먼트 | 낮음 |
| **F2** | **정규화 대칭화** | 두 DB **모두** per-beat z정규 비트로 특징 계산(현재 MIT는 raw) | 낮음 |
| **F3** | **환자 ID 정정** | INCART 레코드→환자 매핑(75→32). 그룹 분할·CI를 환자 단위로 | 낮음 |
| **F4** | **공통 대역 리샘플** | 양쪽을 **낮은 쪽으로** 통일(MIT 360→250/128, 업샘플 금지) | 중간 |
| **F5** | **AF 계층화 보고** | AF 포함/제외 두 숫자 병기 | 낮음 |

> F4 주의: 우리 파이프라인은 300샘플@360Hz 창에 맞춰져 있다. 대역 통일 시
> **MIT-BIH 자체 성능이 변하므로**, 반드시 "동일 대역에서의 MIT-BIH 재측정"을
> 기준선으로 함께 보고해야 한다. 그렇지 않으면 DB 차이와 대역 차이가 교란된다.

## 4. 모델 측 준비

### 4.1 Phase A/B (2리드) — 변경 최소
- 리샘플만 맞추면 기존 구조 그대로 사용 가능.
- `auto_weights`가 DS1 통계에서 Sw를 자동 유도하므로 **S 유병률이 다른 DB에
  자동 적응**한다(MIT-BIH 10.99 → S-rich DB 1.92 검증됨). 하드코딩 없음.

### 4.2 Phase C (Icentia11k, 단일리드) — 구조 변경 필요
| 항목 | 현재 | 변경 |
|---|---|---|
| 입력 | `beat[N,2,300]` | `beat[N,1,L]` — Conv1d 입력 채널 2→1 |
| VCG / XLEAD | 2리드 전제 | **사용 불가** → 제외 |
| WST/MORPHO/REPOL | 리드별 계산 후 결합 | 단일리드로 축소(차원 감소) |
| **RHYTHM** | RR 기반, 리드 무관 | **그대로 사용 가능** ★ |
| robust_template | 리드별 | 단일리드로 동작 |
- **핵심**: 우리 최대 성과인 RHYTHM은 리드 수에 무관하므로 **단일리드에서도 살아남는다.**
  오히려 형태 축이 약해지는 만큼 리듬 축의 상대 기여가 커질 것으로 예상된다(검증 대상).
- 규모 대응: 20억 비트 전체는 불필요. **환자 1,000명 층화 표본**이면 ±0.02 달성.

## 5. 비교 모델 (동일 프로토콜로 재구현)

> **원칙**: 타 논문의 보고 수치를 인용해 비교하지 않는다(PAPER.md §2.2). **같은 데이터,
> 같은 분할, 같은 지표(환자매크로 F1)** 로 우리가 직접 돌린 것만 비교한다.

| 층위 | 모델 | 목적 |
|---|---|---|
| B0 | **다수결(항상 N)** | 자명한 하한 |
| B1 | **de Chazal 2004형**: 형태+RR 특징 → LDA | 고전 기준선 |
| B2 | **표준 1D-CNN** (특징 없이 raw beat만) | 딥러닝 최소 기준선 |
| B3 | **1D-CNN + RR 특징** | 흔한 실무 구성 |
| B4 | **본 연구(형태+리듬+라벨프리 개인화)** | 제안 |
| B5 | (선택) 공개 구현체 1종 | 외부 검증 |

**필수 보고 항목** (모든 모델 공통):
1. **환자단위 매크로 F1** (주 지표) + 95% CI
2. micro F1 (참고, 지배 레코드 명시)
3. S_PR-AUC (임계 무관)
4. **레코드별 분해** + 최다 S 레코드의 기여율
5. 동일 시드 수·동일 앙상블 절차

**B5 주의**: 공개 구현체를 쓸 경우 **우리 분할·우리 지표로 재실행**해야 하며,
원 논문 수치를 그대로 옮기면 §2.2 위반이다.

## 6. 평가 프로토콜 (확정)

```
주 지표      : 환자단위 매크로 F1 (S>0 환자만)   ← 유일 채택 기준
보조         : #최다S레코드 제외 micro, S_PR-AUC(전체/제외)
분할         : 환자 단위 grouped repeated CV (단일 레코드 지배 방지)
              + 관례적 고정 분할(비교가능성 위해 병기)
임계         : held-out calib(학습측)에서만 결정. 오라클은 상한 참고로만 병기
선택         : 검증기반 선택 금지(PAPER.md §6.3) → 무지도 트림 앙상블
불확실성     : 환자 부트스트랩 95% CI 필수. 단일 소수점 주장 금지
검정력       : 사전에 N으로부터 검출 가능 효과를 계산해 명시
음성 결과    : 그대로 보고
```

### 6.1 사전 등록형 가설 (결과 보기 전에 고정)
| ID | 가설 | 기각 조건 |
|---|---|---|
| H1 | RHYTHM 축이 S 판별에 필수 | 형태만 vs +RHYTHM의 매크로 F1 차가 CI 안 |
| H2 | 라벨프리 개인화가 정밀도를 개선 | FP 절감이 유의하지 않음 |
| H3 | 라벨프리 개인화가 매크로 F1을 개선 | **MIT-BIH에서 이미 기각됨**(0.338→0.334). 재검증 |
| H4 | 동작점은 도메인 간 전이되지 않는다 | calib→test 갭이 CI 안으로 축소 |
| H5 | micro는 최다 레코드에 지배된다 | 새 DB에서 micro≈매크로 |

> H3·H5는 특히 중요하다. MIT-BIH에서 관찰한 것이 **일반 현상인지 이 DB 고유인지**를
> 가르는 시험이다. H5가 새 DB에서 기각되면(= micro≈매크로), 우리의 C1 주장은
> "MIT-BIH DS2에 국한된 현상"으로 축소해서 보고해야 한다.

## 7. 단계별 작업 계획

### Phase A — MIT-BIH SVDB (권장 시작점)
1. `svdb_prep.py`: wfdb 다운로드 → AAMI 매핑 → 128→360Hz 리샘플 → **R 재정합(F1)**
   → per-beat z정규(F2) → `svdb_data.npz`
2. 특징 계산(`colab_prep_all.py` 재사용, 경로만 교체)
3. 환자 단위 grouped repeated CV로 B0~B4 전 모델 실행
4. 매크로 F1 + CI + 레코드별 분해 보고
- **산출**: 검정력 ±0.07에서의 정직한 성능, H1·H3·H5 1차 검정

### Phase B — INCART 재실행 (수정본)
1. F1~F5 전부 적용해 `colab_crossdb.py` 갱신
2. **MIT-BIH↔INCART 양방향** 전이 + **INCART 내부 CV**(32환자)
   - 내부 CV가 낮으면 천장은 INCART 자체 → 전이 실패가 아님(중요한 통제)
3. AF 포함/제외 병기
- **산출**: 교차DB 수치를 하한이 아닌 정당한 값으로 갱신

### Phase C — Icentia11k
1. 단일리드 구조 적응(§4.2)
2. 환자 1,000명 층화 표본 추출
3. B0~B4 비교 + 검정력 ±0.02에서의 최종 결론
- **산출**: 논문의 주 결과. 모든 가설의 결정적 검정

## 8. 예상 산출물과 논문 구성 변화

대규모 DB 결과가 나오면 PAPER.md는 다음과 같이 강화된다:
- §6.1 성능: 16환자 ±0.16 → **수백~1,000환자 ±0.02~0.07**. 비로소 방법 주장이 가능.
- §2.2 비교 불가능성: **동일 프로토콜 재구현 비교표**로 대체 → 진짜 비교 성립.
- C1(232 지배): 새 DB에서 **재현되면 일반 현상**, 안 되면 MIT-BIH 국한으로 축소.
- §7 음성 결과: 검정력이 확보된 상태의 음성 결과는 **훨씬 강한 주장**이 된다
  ("검출 못 함"이 아니라 "효과가 0.02 미만임을 보임").
