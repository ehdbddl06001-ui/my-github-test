## 0. 한 줄 요약

기존 파이프라인은 "리듬이 전부"(Δ+0.320)라는 결론을 얻어 놓고도, 그 리듬을
**RHYTHM 10차원 + RR 2차원 = 12개 스칼라**로 접어서 분류기에 곁들인다.
RSN 은 그 병목 하나만 푼다 — **±8박 RR 시퀀스를 주 인코더가 직접 처리**하고,
형태는 용량 1/4의 보조 가지로 내린다. 구조는 오히려 **단순해진다**(게이트·프로토타입·샴 제거).

## 1. 왜 이 설계인가

### 1.1 근거 (HANDOFF §3, PAPER §6.2 / §8.1)

| 사실 | 함의 |
|---|---|
| CNN(형태만) 0.164 → CNN+RR 0.484 (Δ+0.320, 보정 후 유지) | 리듬이 판별의 본체 |
| 제안모델 − CNN+RR = +0.050 (비유의) | 구조 정교화는 이득 없음 |
| S는 **조기성(timing)** 으로 정의되고 QRS 형태는 N과 같다 | 생리학이 위 둘을 설명 |

두 결과를 나란히 놓으면 남는 처방은 하나다: **정보의 종류(리듬)에 투자하고,
처리의 정교함(구조)에는 투자하지 않는다.**

### 1.2 병목 진단 — 스칼라 압축이 무엇을 버리는가

현행 RHYTHM innovation(§4.2)은 환자별 인과 EWMA 잔차를 **비트당 스칼라**로 만든다:

```
innov[t] = tanh( (RR[t] − pred[t]) / (3·MAD) )     ← 비트 하나당 숫자 하나
```

이 스칼라는 "이 박이 예상보다 얼마나 빨랐나"는 담지만, **패턴**은 담지 못한다:

| 리듬 패턴 | 임상 의미 | 스칼라 innovation 이 구분하는가 |
|---|---|---|
| 짧고-긴 1회 (조기박 + 불완전 보상휴지) | 단발 APC | 부분적 |
| 짧-긴-짧-긴 반복 | bigeminy | **불가** (각 박이 같은 값) |
| 짧-짧-긴 | couplet | **불가** |
| 지속적 불규칙 | AF | **불가** (N1 실패의 근원) |
| 점진적 가속/감속 | 동성 부정맥(정상) | **불가** — 위양성의 원천 |

마지막 줄이 특히 중요하다. **동성 부정맥(정상 변이)과 이소성(병적)은
단일 박의 조기성으로는 구분되지 않고, 앞뒤 박의 문맥으로만 구분된다.**
스칼라로 접는 순간 이 정보가 사라지고, 모델은 그것을 되찾을 방법이 없다.

### 1.3 그래서 무엇을 바꾸는가

```
[기존]  RR 2개 ─┐
       RHYTHM 10개 ─┼→ (다른 8개 특징군 145차원과 함께) → 분류기
       형태 CNN 128차원 ─┘        ↑ 리듬은 12/157 = 7.6%

[RSN]  RR 시퀀스 [4채널 × 17슬롯] → TCN(dilation 1-2-4) → 64차원  ← 주(主)
       형태 raw beat [2 × 300]   → 소형 CNN            → 16차원  ← 보조
       스칼라 보조 10차원         → MLP                 → 16차원
                                   → concat → 64 → 3   ↑ 리듬은 64/96 = 67%
```

**용량 배분 자체가 가설의 표현이다.** 리듬 64 : 형태 16 = 4:1.

## 2. 구성 요소

### 2.1 RR 문맥 시퀀스 (`rr_context`)

구간열을 `svdb_prep.py` 의 저장 규약에서 유도한다:

```
Aext = [pre_rr[0], pre_rr[1], ..., pre_rr[n-1], post_rr[n-1]]     (레코드당 길이 n+1)
비트 j 의 창 = Aext[j-8 .. j+8]  (길이 17)
  슬롯 k=0  → 자기 pre-RR  (조기성)
  슬롯 k=+1 → 자기 post-RR (보상성 휴지) ← APC/PVC 분리의 핵심
```

4개 채널 — **전부 무차원**이라 심박수·환자·기기에 불변이다(§4.2의 설계 철학 계승):

| ch | 정의 | 담는 것 |
|---|---|---|
| 0 | `clip(log(RR_q / med_j), ±1.5)` | 심박수 불변 상대 길이 |
| 1 | `clip(dRR_q / med_j, ±1.5)` | 박간 변화(짧-긴 교대 패턴) |
| 2 | `tanh(innov_q / 3·MAD_j)` | **기존 RHYTHM 과 같은 양, 단 슬롯마다 보존** |
| 3 | `mask` | 유효 슬롯 표시(경계·구멍·생리범위 밖 = 0) |

`med_j`·`MAD_j` 는 **직전 128박 이동창**에서 구한다 → 인과적이고 라벨을 쓰지 않는다.

> **PAPER §9-6 지적의 해소**: `_pp_center2` 는 레코드 전체 비트로 중심을 추정하는
> transductive 방식이라 스트리밍에 못 쓴다는 한계가 기록돼 있었다. RSN 의 정규화는
> 처음부터 인과적 이동창이라 이 문제를 만들지 않는다. `causal_only=True` 면
> 미래 슬롯(k≥2)도 마스킹되어 **1박(≈0.8초) 지연의 실시간 구현**이 가능하다.

### 2.2 경계·구멍·이상치 처리 (조용한 오염 차단)

세 가지를 명시적으로 끊는다. 셋 다 자기검증으로 확인한다.

1. **레코드 경계** — 창이 다른 환자로 넘어가지 않는다. (GroupKFold 누설 방지)
2. **건너뛴 비트** — `svdb_prep` 은 F/Q 등 AAMI 밖 심볼을 버린다. 그 지점에서
   `post_rr[j] ≠ pre_rr[j+1]` 이 되어 구간열에 구멍이 생긴다. 구멍을 넘어 참조하는
   슬롯은 `mask=0` 으로 끊는다 — **없는 연속성을 학습하지 않게** 한다.
3. **생리범위 밖 RR** — `[0.20s, 3.0s]` 밖은 결측 처리한다.

> **③에 관한 데이터 위생 경고 (신규 발견, 미검증)**
> `svdb_prep.py` 는 `rr = np.diff(ann.sample)` 로 RR 을 만든 뒤 **비트 단계에서만**
> AAMI 밖 심볼을 거른다. WFDB 주석열에는 `'+'`(리듬 변경) 같은 **비-비트 주석이
> 자기 샘플 위치를 갖고 섞여** 있으므로, 그 직후 비트의 `pre_rr` 이 0에 가까워질 수
> 있다. 그렇게 되면 기존 RHYTHM innovation 이 거대한 잔차를 만든다 —
> STEP49 가 MIT-BIH 에서 겪은 '스케일 폭발'과 같은 종류의 오염이다.
> **이는 B3/B4 를 포함한 기존 수치에도 영향을 줄 수 있다.**
> `rr_audit()` 이 실제 규모를 1분 안에 정량화한다. **먼저 돌려볼 것.**
> 규모가 무시할 수준이면 기존 결과는 그대로 유효하고, 크면 별도 이슈로 다뤄야 한다.

### 2.3 인코더

**리듬 가지 (주)**: dilation 1-2-4 의 3층 TCN. 수용야 17 = 창 전체를 정확히 덮는다.
풀링은 `[GAP, k=0 탭, k=+1 탭]` 을 이어 붙인다 — GAP 만 쓰면 판별의 주역인 자기 박이
17분의 1로 희석되므로, 전역 문맥과 자기 박을 **둘 다** 남긴다.

**형태 가지 (보조)**: 채널 폭을 B2/B3(32-64-128)의 **1/4**(16-32-32)로 줄인 소형 CNN.
결론1에 따라 형태에 용량을 쓰지 않되, **V 판별에는 형태가 유효**하므로(PAPER §6.5:
V는 리듬 없이도 전이됨, V_PR 0.690) 3-class 문제에서 제거하지는 않는다.

**융합**: 게이트·프로토타입·샴 **없음**. 단순 concat → 2층 선형 헤드.
결론2가 이것들의 이득 부재를 보였으므로 되풀이하지 않는다.

총 파라미터 **약 52,000** — B4 대비 대폭 축소.

### 2.4 하지 않은 것 (§4 실패 목록 준수)

| 실패 | RSN 이 피한 방법 |
|---|---|
| N0 9특징군 + 샴/게이트/프로토타입 | 전부 제거. 특징 캐시(WST/MORPHO/…)를 **하나도 안 씀** |
| N1 리듬 신뢰도 게이트 | **차단하지 않는다.** §2.5 참조 |
| N6/N12 환자 임베딩·FiLM | 환자 식별 정보 없음. 정규화는 이동창 통계뿐 |
| N7 다중비트 컨텍스트(형태) | 형태는 단일 비트만. 다중비트는 **리듬 축에서만** |
| N13 라벨프리 개인화 | 채택 안 함(2회 독립 기각됨) |

### 2.5 Poincaré 채널이 N1 과 다른 이유 (R2 한정)

N1 은 '리듬 불규칙도' 스칼라로 **RR 축을 하드 차단**했고, 그 지표가 표적에 오염돼
(#232 = AF 가 아니라 APC 76%) S 많은 환자에서 **S를 잡는 바로 그 축을 스스로 껐다**.

R2 는 같은 정보를 **입력 채널로만** 준다. 차단 로직이 없으므로 자기파괴 루프가
구조적으로 불가능하고, 그 정보를 얼마나 믿을지는 **학습 폴드가 정한다**.
5개 통계(sd1/med, sd2/med, sd1/sd2, 이산성, 첨도 대용)가 AF('불규칙하게 불규칙' →
확산 구름)와 이소성('규칙 + 간헐 조기박' → 이산 군집)의 분리를 담당한다 —
PAPER §7-N1 이 "원리적 수정 방향(미실행)"으로 남긴 것이 이것이다.

## 3. 사전등록 (결과를 보기 전에 고정)

### 3.1 가설

| ID | 가설 | 판정 기준 |
|---|---|---|
| **H-A** | **주가설.** R1(RSN) 이 B4 대비 유의하게 낫다 | Δ ≥ **+0.07** **그리고** Bonferroni(k=3) 보정 CI 가 0 배제 |
| H-B | 시퀀스화의 순효과: R1 > B3(CNN+RR) | 같은 RR 정보를 스칼라로 줬을 때와의 차. **기전 확인용** |
| H-C | 형태 가지의 기여: R1 > R0(리듬만) | 절제. 비유의여도 결론1과 **정합**(형태는 원래 기여가 작다) |
| H-D | Poincaré 채널: R2 > R1 | 탐색적. N1 의 원리적 수정이 되는지 |

### 3.2 규율

1. **결과를 보고 주가설을 바꾸지 않는다.** H-A 가 실패하면 실패로 기록한다.
2. **Bonferroni k=3** (R0/R1/R2 대 B4). 보정 후 유의한 것만 "확증"이라 쓴다.
3. **주변 CI 비교 금지.** 반드시 대응 부트스트랩(같은 환자의 F1 차이).
4. **Δ < +0.07 은 개선이라 부르지 않는다.** 73환자의 검출 한계다.
5. **좋게 나오면 먼저 의심한다.** N3(SMOTE 0.821 → 재실행 0.796)의 교훈.
   H-A 가 지지되면 `n_rep=3` 재실행으로 재현을 확인하기 전까지 확증이라 쓰지 않는다.
6. **음성 결과도 PAPER §7 에 기록한다.**

### 3.3 공정 비교 보장

RSN 은 B2/B3/B4 와 다음을 **모두 동일**하게 맞춘다 — 달라지는 것은 **입력 표현과
인코더뿐**이다.

| 항목 | 값 | 출처 |
|---|---|---|
| 폴드 | 환자 GroupKFold(5), 동일 seed | 하니스가 부여 |
| calib | 학습셋에서 환자 분리 25% | 하니스가 부여 |
| 임계 | `_best_t_f1(calib)` — **test 라벨 미사용** | 하니스가 부여 |
| 불균형 가중 `Sw` | `auto_weights(y[tr])` — 학습셋 유도 | 하니스가 부여 |
| LDAM 마진 `mc` | `1/n_c^0.25` 정규화 — 학습셋 유도 | 하니스가 부여 |
| 옵티마이저 | AdamW lr 1e-3, wd 1e-4 | 동일 |
| epoch / batch / clip | 15 / 512 / 1.0 | 동일 |
| 시드 수 | **1** (`n_seed=1`) | 동일 |

> `n_seed>1`(softmax 앙상블)은 구현돼 있으나 **주 비교에 쓰지 않는다** —
> B2~B4 가 단일 시드이므로 앙상블은 부당한 분산 이득이 된다(PAPER §6.7).

### 3.4 미리 정한 해석

| 결과 | 어떻게 쓸 것인가 |
|---|---|
| H-A 지지 (Δ≥0.07, 보정 후 유의, 재현됨) | **결론1의 실행적 귀결**: 리듬은 정보로서만이 아니라 **표현 형식으로도** 중요하다 |
| H-A 실패, H-B 지지 | 시퀀스화는 B3 를 넘지만 B4 의 9특징군과 동급 → "다른 경로로 같은 천장" |
| 둘 다 실패 | **정보 포화 가설(§8.4-1)의 강한 증거** — RR+형태로 이미 포화. PAPER §7 에 N14 로 기록 |
| R2 만 지지 | AF/이소성 분리가 실제 이득 → N1 의 원리적 수정 성공 |

**세 번째 줄이 중요하다.** 이 설계는 실패해도 정보를 준다. 리듬을 가장 직접적인
형식으로 줬는데도 이득이 없다면, 남은 병목은 표현이 아니라 **라벨 천장(§8.4-2)이나
표본 한계(§8.4-3)**라는 뜻이고, 그러면 다음 행선지는 모델이 아니라
**Icentia11k(1,000+환자)** 다.

### 4.1 하니스 확장 방식

`svdb_bench.py` 에 **arm 레지스트리**를 추가했다(기존 arm 의 동작은 불변):

```python
register_arm(name, fn)     # fn(ctx) -> bool[len(ctx["te"])]
clear_arms(); list_arms()
```

`bench_models()` 는 각 폴드에서 등록된 arm 을 **B0~B4C 와 동일한 `tr/cal/te/Sw/mc/seed`**
로 호출한다. 따라서 새 모델은 자동으로 같은 조건에서 평가되고, 환자별 F1 벡터
(`RES[arm]['fper']`)가 같은 환자 순서로 정렬되어 **대응 부트스트랩이 유효**하다.

arm 이 예외를 던지거나 길이 계약을 어기면 **그 arm 만 결과에서 제외**되고 나머지

증거가 일관된다:

## 12. 4차 사전등록 (R7 적응 임계, 결과 보기 전 고정)

**무결성**: 테스트 환자 라벨 미사용(§7-1), 개인화는 본인 신호만(§7-3),

⚠ **한계**: 레코드 전체 점수로 분위를 잡으므로 **transductive**

**결론: 이 데이터에서 SVEB 검출을 실제로 움직이는 것은 "리듬을 어떻게 표현하는가"

### 16.2 규율 — 지표를 바꾸지 않는다

+0.018 은 매력적이지만 **주 지표를 'N/S/V 평균'으로 갈아타지 않는다.** 결과를 본
뒤 지표를 고르는 것이 사후 골대이동이고, §13.2 에서 R7 을 살리지 않은 것과 같은
이유로 여기서도 하지 않는다. 5클래스 평균을 주 지표로 유지하고 위 분해는
**분해로만** 쓴다.

또한 **+0.018 은 아직 유의하지 않다.** 환자 201명이면 MDE ≈ 0.042
(= 0.07 × √(73/201)) 이고 +0.018 은 그 아래다. 대응 부트스트랩으로 확인하기
전까지 "통합+미세조정이 N/S/V 를 개선한다"고 말할 수 없다.

### 16.3 이 결과가 2층 설계에 미친 영향

- **F·Q 는 1층에서 더 추격하지 않는다.** F 는 45레코드 1,044비트(레코드당 23개),
  Q 는 DB 인공물이다. 둘 다 데이터 문제이지 모델 문제가 아니다.
- **통합 학습은 유지하되 미세조정을 붙인다** — P2 > P1 이 **5클래스 전부**에서
  성립한다(유일하게 방향이 일관된 효과). 다만 P2 는 P0 도 넘어야 의미가 있는데
  DB별로는 svdb 에서만 넘었다(0.443 vs 0.438). 통합의 값어치는 아직 미확정이다.
