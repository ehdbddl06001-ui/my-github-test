## 0. 가장 먼저 — 시각 자료에는 서로 다른 두 lane이 있다

**둘은 원천도, 공개 여부도, 만드는 방법도 다르다. 절대 섞지 말 것.**

| | **A. 자체 제작 모식도 lane** | **B. 실사 복원 lane** |
|---|---|---|
| 원천 | 없음 — 해부학 지식 + 강의 텍스트로 **새로 그린다** | 사용자가 업로드한 **실제 카데바·e-Anatomy 캡처 스캔** |
| 도구 | 손으로 쓰는 SVG (`docs/assets/anatomy/*.svg`) | `pipelines/restore_scan.py` |
| 결과 | `asset_origin: claude-drawn-svg` | `asset_origin: restored-scan` |
| 공개 | ✅ `publishable: true` 가능 (저작권·존엄 문제 없음) | ❌ `publishable: false` **고정** |
| 저장 | `docs/assets/anatomy/` (repo·웹 공개) | `.private/anatomy/render/` (gitignore) |
| 전달 | 웹 번들 + repo | 채팅 파일 전송 · PDF · (텍스트만) Drive |

> **중요 — 흔한 오해**: A의 모식도는 B의 카데바 사진을 **보고 따라 그린 것이 아니다.**
> 실제 사진의 구도·조직 형태를 옮기지 않는다. A는 "교과서 표준 구도 + 강의에서 확인된
> 관계"만으로 그린 독립 저작물이고, B는 원본 사진 자체를 손대지 않고 필기만 지운 것이다.
> 사진을 트레이싱해서 SVG로 만드는 것은 **파생저작물**이 되므로 하지 않는다.

두 lane 모두 산출물은 **라벨판 + 퀴즈판 쌍**으로 만든다(§3).

## 1. Lane A — 자체 제작 SVG 모식도

### 1-1. 무엇을 그리는가 (회차마다 최소 3종)

1. **근육층 도해** — 얕은층 → 깊은층 순서. 층마다 지배신경 규칙을 색으로 구분.
2. **신경 도해** — 분지·주행·지배 근육. 감각/운동 구분.
3. **혈관 분지 도해** — 모동맥 → 가지 트리. 문합은 닫힌 고리로.

한 도해가 둘을 겸할 수 있다(예: 큰궁둥구멍 도해는 신경 + 혈관 동시).

### 1-2. 실측으로 얻은 작화 규칙 (2026-08-14)

- **층을 한 그림에 겹쳐 그리지 말 것.** 첫 시안에서 얕은/중간/깊은층을 한 몸통에
  겹쳐 그렸더니 위 층이 아래 층을 가려 아무것도 안 읽혔다. → **층별 분할 패널**
  (같은 몸통 실루엣을 `<defs><g id="torso">` 로 정의하고 `<use>` 로 3번 반복)이 정답.
- 라벨은 **그림 밖 여백 열**에 두고 얇은 지시선으로 연결한다. 그림 위에 얹으면
  구조를 가린다. 여백이 없으면 패널을 줄여서라도 여백을 만든다.
- **패널 경계를 넘는 라벨 금지.** 패널 `rect` 의 x범위 안에 텍스트 폭이 들어가는지
  계산할 것(한글 ≈ font-size × 1.0, 영문 ≈ × 0.5 로 어림).
- 회전 라벨(`transform="rotate()"`)은 근육 위에 쓸 때만. 회전 텍스트는 충돌 검사가
  어려우니 최대 1~2개.
- 텍스트 후광 필수: `<style>text{paint-order:stroke;stroke:#0e1826;stroke-width:3.2px}</style>`
- 색 팔레트(기존 도해와 통일): 배경 `#0e1826` · 뼈 `#1b2a3c`/`#3d5166` ·
  본문 `#e6edf3`/`#93a4b7` · 신경 `#9cc3ff` · 동맥 `#e0645f` · 뒤가지/깊은층 `#f0b56b` ·
  강조·핀 `#eab308` · 더부신경 등 특수 `#c9a5f0`
- **전 라벨 한·영 병기.** 범위 표기는 `–`(en dash) — `~`는 Google Docs 변환에서
  취소선으로 깨진다.
- 특정 교과서 도판을 복제하지 않는다(구도만 참고). 강의에서 확인된 관계만 담는다.

### 1-3. QA 루프 (커밋 전 필수, 최소 1회 왕복)

```bash
/opt/pw-browsers/chromium --headless --disable-gpu --no-sandbox \
  --screenshot=/tmp/qa.png --window-size=880,700 --hide-scrollbars \
  file://$PWD/docs/assets/anatomy/<파일>.svg
```

렌더한 PNG를 **눈으로** 보고 체크: ① 라벨-라벨/라벨-구조 겹침 ② 패널·캔버스 밖 넘침
③ 번호 가독(원문자 글리프 ①② 금지 — 원 도형 + 일반 숫자) ④ 해부학적 위치관계가
카드 본문과 모순 없는지 ⑤ 좌우대칭 `<use>` 미러 깨짐. 스크린샷 확인 없이 커밋 금지.

## 2. Lane B — 실사 복원 (업로드 스캔)

`pipelines/restore_scan.py` — 필기 제거 → 정답 라벨/자막/타이틀 가림 → 번호핀.

### 2-1. 절차

```bash
# 1) 페이지 렌더 (폭 1650px 고정 — bbox 좌표계를 일정하게)
python3 -c "import pymupdf,cv2,numpy as np; ..."   # 회차별 페이지 선정 후
# 2) 좌표 확인: 격자 오버레이를 얹어 눈으로 읽는다
# 3) config JSON 작성 (.private/anatomy/cfg/<페이지>.json)
python pipelines/restore_scan.py --image <page>.png --config <cfg>.json \
    --out-clean <...>_clean.png --out-quiz <...>_quiz.png
# 4) 렌더 QA → bbox 보정 → 재실행 (보통 2~3회 왕복)
```

### 2-2. config 키 (실측으로 하나씩 추가된 것들)

| 키 | 언제 쓰나 |
|---|---|
| `colors` + `protect` + `olive_region` | 색 필기(빨강/파랑/올리브) 자동 검출. 장갑·영상 라벨·파란 수술복은 `protect` |
| `stroke_boxes` | **검정** 손글씨 — 박스가 아니라 획 픽셀만 마스킹 |
| `bright_stroke_boxes` | **흰** 손글씨 — 박스째 지우면 그 안의 정답 근육까지 날아간다. 배경 커널 61px·pad 3 |
| `keep_boxes` | 영상 ▲ 포인터처럼 **지우면 안 되는 그래픽**이 필기 박스와 겹칠 때. `protect`는 색 검출에만 걸려 획 마스크를 못 막는다 |
| `donor` | 같은 영상의 인접 프레임에서 진짜 조직 질감 복사(고정 카메라라 대부분 성립) |
| `label_boxes` | 정답 라벨 가림. 점진 인페인팅 + 질감 매칭(+donor)으로 채운다 |
| `title_box` / `black_boxes` | 좌상단 영상 타이틀·하단 자막 — 답이 노출되므로 검은 박스 |
| `crop` | 영상 프레임만 남겨 스캔 여백 필기를 통째로 제거 |
| `pins` | 번호핀 + 지시선 |

### 2-3. 함정 (전부 실제로 당한 것)

- **형광펜이 조직을 넓게 덮은 페이지는 포기하고 다른 프레임을 쓴다.** 지우면 조직이
  하얗게 날아간다(2회차 pf1 p3 넓은등근 프레임 — 폐기하고 p8로 대체).
- **필기가 정답 구조 위에 직접 겹친 페이지**는 지운 자리가 얼룩으로 남는다 →
  `needs_review: true` 로 올리고 카드에 대체 프레임을 적어 둔다(0026 사례).
- **donor는 원본의 "배경"과 비교해야 한다.** 날것 소스와 비교하면 지우려는 흰 필기와
  donor의 흰 장갑이 서로 닮아 보여 장갑이 글씨 자리에 복사된다(수정 완료).
- 라벨 박스는 **글자 윗선까지** 덮어야 한다. 아래만 맞추면 획 끝이 남는다.
- 퀴즈판을 라벨판에서 자동 생성할 때 **지시선·정답 노출 패널이 남는다** — 지운 라벨을
  가리키던 지시선은 허공을 가리키므로 함께 제거.

## 3. 두 lane 공통 — 라벨판/퀴즈판 쌍과 학습 동선

| 산출물 | Lane A | Lane B |
|---|---|---|
| 라벨판(학습·자가채점) | `*-labeled.svg` (공개) | `*_clean.png` (비공개, 필기만 제거·라벨 살아 있음) |
| 퀴즈판(태깅 연습) | `*-quiz.svg` (공개) | `*_quiz.png` (비공개, 라벨 가림 + 번호핀) |

**번호핀 = 대응 문항 카드의 정답 순서와 1:1. 임의 변경 금지.**

학습 동선은 항상 **라벨판으로 익히고 → 퀴즈판으로 답하고 → 문항 카드로 채점**이며,
회차 종합정리(`kind: study_guide`) 맨 앞에 이 표를 붙여 연결한다.

### 카드 3종 세트

- `kind: concept` — 라벨판 + 표/트리 설명 (Lane A만 `web_asset` 으로 공개 연결)
- `kind: question` — 퀴즈판 + `answer`/`explanation` (frontmatter에만)
- `kind: study_guide` — 회차 전체를 묶고 위 표로 동선 제공

## 5. 실사 자료를 Drive로 — 무엇이 되고 무엇이 안 되나 (2026-08-14 실측)

실사 복원본은 웹(MedKOS 홈페이지)에 절대 안 올라간다(§0). 그래서 **개인 Drive가 유일한
보관처**인데, 여기에 결정적인 제약이 있다.

### 왜 클로드가 이미지를 Drive에 직접 못 올리는가

Drive MCP `create_file` 에는 `base64Content` 가 있어 **기능적으로는 가능하다.** 문제는 비용:
클로드가 그 base64 문자열을 **직접 출력**해야 하고, 출력하려면 먼저 파일을 **읽어 컨텍스트에
넣어야** 한다 → 파일 크기의 약 **2배**가 토큰으로 나간다.

| 산출물 | 파일 | base64 | 대략 토큰(읽기+쓰기) |
|---|---|---|---|
| 회차 실사 문제집 PDF(압축본) | 293KB | 391KB | **약 22만** |
| 이미지 1장(1000px q55) | 45KB | 60KB | 약 3.5만 |

주간 이용 한도를 통째로 태울 수 있는 규모라, **기본값은 "올리지 않는다"** 이다.
사용자가 명시적으로 요청하고 한도 여유를 확인했을 때만 예외로 올린다.

### 그래서 실제 배포 경로 (기본값)

| 자료 | 경로 |
|---|---|
| 실사 문제집 **PDF**(문제 이미지 + 정답 이미지) | **채팅 파일 전송** → 사용자가 Drive 폴더에 저장(1회 동작) |
| 실사 문제집 **텍스트 동반본**(문항·정답·해설) | 클로드가 **Drive Docs로 직접 업로드**(텍스트라 비용 없음) |
| 회차 종합정리(study_guide) | Drive Docs 직접 업로드 |
| 자체 제작 도해(SVG) | repo + 홈페이지 공개 — Drive에 올릴 필요 없음 |

Drive 폴더 `MedKOS-해부-복원자료`(id `1W2AYQSr-zzKseja7ppukc1uLMh6CgOGl`)에 회차마다
**"…실사 복원 문제집 — 정답·해설 (PDF 동반본)"** Docs를 올리고, 그 문서 머리에 짝이 되는
PDF 파일명을 적어 둔다. 사용자가 채팅에서 받은 PDF를 같은 폴더에 저장하면
**이미지(문제) + 텍스트(검색 가능한 정답)** 두 벌이 한곳에 모인다.

### PDF 만드는 법

```bash
# 매니페스트: 회차 제목·수업일·범위·개요 + questions[{card, quiz_image, clean_image}]
python pipelines/anatomy_pdf.py --manifest .private/anatomy/pdf/s02_manifest.json
```

용량 옵션(매니페스트 키) — **Drive 저장·모바일 열람용 기본값**:

| 키 | 값 | 용도 |
|---|---|---|
| `image_px` / `image_q` | 900 / 50 | 문제(퀴즈) 이미지 |
| `answer_image_px` / `answer_image_q` | 560 / 42 | 정답(라벨판) 이미지 |

폰트 서브셋(`doc.subset_fonts()`)이 들어 있다 — 넣기 전 2002KB → 넣은 뒤 **293KB**.
한글 폰트를 통째로 심으면 1.7MB를 먹으므로 이 호출을 지우지 말 것.
