## R1. 채점 대상 마스크는 **한 곳에서** 정의하고 모든 집계가 인자로 받는다

같은 오염이 **세 곳**에서 반복됐다:

| # | 어디 | 무슨 일 | 발견 |
|---|---|---|---|
| ① | 부위별 채점 | `GMIN_PT=20` 적용 ✅ | — |
| ② | OR 게이트 | **적용 안 함** ❌ | 실험20c P-3 |
| ③ | 임계값 CV 평균 | **적용 안 함** ❌ | 실험20c 사후 검토 |

②의 대가: 특이도 **0.196 → 0.678**, LR+ **1.24 → 2.74**.
③의 대가: 결론이 **뒤집혔다**(전체 7부위 0.700 vs 0.743 → 채점 3부위 0.790 vs 0.627).

```python
SCORE_MASK = np.array([Y[:, j].sum() >= GMIN for j in range(K)])   # 한 번만
CONFIG["score_mask"] = [SITES[j] for j in np.where(SCORE_MASK)[0]]
def agg(x, mask=SCORE_MASK): ...    # 모든 집계가 받는다
```

### 감사 결과 (2026-08-02)

| 실험 | 상태 |
|---|---|
| 15 · 15c · 15d · 16 · 17 · 18 · 19 · 22 | **해당 없음** — PTB-XL 내부는 `NMIN=50` 을 라벨 수준에 걸었고 7부위가 전부 통과한다. 배제 대상이 애초에 없다 |
| 20 | 정상 — 표에 `⚠️채점제외` 를 찍고 `SCORE_SITES` 로 채점 |
| **20b** | **오염** — 7부위 OR 에 제외 부위를 그대로 넣었다 |
| **20c** | **오염** — CV 평균에 제외 부위를 그대로 넣었다 |
| 20d | 수정 — `SCORE_MASK` 도입 |
| 21 | 설계에 반영됨(미실행) |

⚠️ **다만 내부 실험에 별개의 사촌 문제가 있다.** 실험16~19 의 `최악 D = max(부위)` 는
7부위 전체의 최댓값이라 **가장 시끄러운 부위가 지배**한다 — 실제로 `IPLMI`(n=51,
`NMIN=50` 을 겨우 넘김, SD 0.043)가 끌고 갔다. 이건 배제 대상이 아니므로 오염은
아니지만, **max 통계량은 항상 "무엇이 끌고 가는지" 와 중앙값을 함께 보고**해야 한다
(실험18 카드가 이미 그렇게 했다).

## R4. 유병률에 붙은 지표로 **코호트를 비교하지 않는다**

| 지표 | 코호트 간 비교 | 이유 |
|---|---|---|
| **AUROC** | ✅ | 순위 기반 · 유병률 무관 |
| 민감도·특이도 | ✅ | 조건부 확률 |
| PPV·PR-AUC | ❌ | 유병률에 직접 붙는다 |
| lift (= PR / 기저율) | ⚠️ | **천장이 `1/기저율`** 이라 코호트마다 다르다 |

실측 사례: MIT-BIH DS2 lift 천장 26.8× vs INCART 89.3× — 3배 넘게 다르다.

→ **축·코호트를 가로지르는 비교는 AUROC 로 한다.**

## R5. 집계 방식이 **결론을 만들어내지 않는지** 확인한다

실험20c 의 P-2 는 `|narrow − wide| < 0.05` 였는데, `wide` 를 두 헤드 AUROC 의
**산술평균**으로 잰 탓에

```
강 − 평균 = (강 − 약) / 2
```

이 되어 **약한 헤드가 문턱의 2배만 뒤처지면 자동 기각**됐다. 실측 `(0.8660−0.5684)/2
= 0.1488` 로 문턱 0.05 를 구조적으로 넘었다. 실험20d 가 결합 점수 `max()` 로 다시
재니 차이가 **0.0017** 이었다 — **데이터가 아니라 통계량이 말한 것**이었다.

→ 관문을 쓰기 전에 **영가설에서 그 통계량이 어떤 값을 내는지** 픽스처로 확인한다.

같은 종류로 걸렀던 것: 실험21 의 P-4 를 `단일 SD / LOO앙상블 SD ≥ 1.5` 로 재려 했는데,
LOO 앙상블 5개는 서로 4/5 를 공유해 **효과가 0 이어도 비가 정확히 4.00** 이 나온다.

## R10. 확률을 저장할 때 **정답 라벨과 인덱스를 같이** 저장한다

2026-07-17 실행의 pkl 10개에는 `proba`·`pred`·`f1`·`macro4` 가 들어 있는데
**`y` 가 없다.** 그래서 실험22-A 가 라벨을 현재 파이프라인의 DS2 배열에서
빌려오려 했고, 길이가 **47,801 vs 49,295** 로 어긋나 재계산이 막혔다.

두 가지가 동시에 걸린 것이다:

| # | 문제 | 결과 |
|---|---|---|
| ① | 라벨 미저장 | 확률만으로는 어떤 지표도 재계산할 수 없다 |
| ② | 비트 추출 파이프라인이 그새 바뀜 | 외부에서 빌린 라벨과 **정렬이 안 맞는다** |

②가 없었다면 ①은 티가 안 났을 것이다 — 그래서 **둘 다** 위험하다.
길이가 우연히 같으면 어긋난 라벨로 조용히 **다른 실험**을 하게 된다.

→ 저장 규격: `proba` 와 함께 **`y`·`pid`·`beat_index`** 를, 그리고 그 실행이 쓴
**데이터 캐시 파일명과 해시**를 넣는다. 길이만 맞는지 보고 정렬을 가정하지 않는다.

### R10-b. **길이 일치는 정렬의 증거가 아니다** — 클래스 구성까지 대조한다

47,801 은 **서로 반대 방향 두 오차의 상쇄값**일 가능성이 높다:

```
겉보기 차이 = (N/S/V 부족)  −  (제4클래스 F 초과)
```

07-17 실행은 **4클래스**(N/S/V/F)였다. 그 증거가 pkl 안에 이미 있었다 — 키 이름이
`macro4` 이고, `nsv` 는 N/S/V **셋만** 센다. 따라서 `nsv` 합과 `len(proba)` 의 차액이
곧 F 개수다. 이걸 안 보면 부족과 초과가 상쇄돼 겉보기 차이만 작아 보인다.

**최악의 경우 길이가 정확히 일치하면서 정렬은 완전히 어긋난다.** 그러면 아무 경고
없이 채점된다. 이번엔 운 좋게 안 맞아서 걸린 것이다.

→ 정렬을 인정하는 조건은 **길이 AND 클래스별 개수**다. 하나만으로는 안 된다.

### R10-d. 데이터 손실을 **풀링 비율**로 보고하지 않는다

2026-08-02 실측. 07-17 캐시가 현재 파이프라인보다 3,260비트(3.26%) 적었다.
"전 레코드에 3~4% 씩 고르게" 로 읽혔는데, 레코드별로 보니 정반대였다:

| | |
|---|---:|
| 손실 **0** 인 레코드 | 13 / 44 |
| 손실률 5% 초과 | 3개 (#114 · #203 · #228) |
| **#228(80.6%) + #114(46.0%)** | 전체 부족의 **77.2%** |

풀링 비율 3.26% 는 **두 레코드의 사고를 42개로 나눠 희석한 값**이었다.

→ 손실은 항상 **① 레코드별 최악값 ② 손실 0 인 레코드 수 ③ 상위 2개의 누적 기여**
와 함께 보고한다. 평균만 내면 "고르게 조금씩" 으로 오독된다.

### R10-e. **N 이 멀쩡한데 특정 클래스만 빠지면 검출이 아니라 라벨 매핑이다**

R파 검출·분절 실패는 **클래스에 눈이 멀다**(class-blind) — 라벨을 보고 비트를 고르지
않는다. 그러므로 다음은 검출 실패로 **산술적으로 불가능**하다:

| rec | N 손실 | S 손실 | V 손실 |
|---|---:|---:|---:|
| #201 | 1/1,635 (0.06%) | **66/128 (51.6%)** | 0 |
| #210 | 4/2,421 (0.17%) | **13/22 (59.1%)** | 35/195 (17.9%) |
| #124 | 0/1,535 (0%) | 0/31 (0%) | **31/47 (66.0%)** |
| #202 | 0/2,060 (0%) | 7/55 (12.7%) | **12/19 (63.2%)** |

같은 기록 안에서 시간적으로 섞여 있는 비트들이다. 남은 설명은 **심볼→AAMI 매핑**뿐:
S군 = `A`+`a`+`J`+`S` (aberrated APB `a` 누락 의심) · V군 = `V`+`E`
(ventricular escape `E` 누락 의심).

→ 손실을 진단할 때 **클래스별 손실률을 레코드 안에서** 비교한다. N 손실률 ≈ 0 인데
다른 클래스만 크면 검출 가설을 버린다. 확정은 `wfdb.rdann` 심볼 카운트로.

### R10-c. '레코드 소실 vs 분산 손실' 은 **클래스 프로파일**로 가른다

비트 수 차이만 보면 애매하다(DS2 레코드당 평균 약 2,241비트라 1,872 는 0.84
레코드분이다). 그런데 DS2 는 **한 레코드(#232)가 S 의 75.2% 를 갖는다**
(`mit-bih/PAPER.md` 관찰3). 그래서:

| 관측 | 함의 |
|---|---|
| S 손실이 최대 보유 레코드에 근접 | 그 레코드가 통째로 빠졌다 |
| S 손실이 그보다 훨씬 작고 클래스별로 고르다 | **전 레코드 분산 손실** |

⚠️ 이때 기준값(#232 의 S 개수)은 **인용하지 말고 우리 배열에서 직접 센다.**
픽스처 `pipelines/test_exp22a_g1.py` 의 A/E 시나리오가 이 판별을 검정한다 —
가짜 07-17 배열을 **현재 배열에서 파생**시켜야 한다는 것까지 포함해서(독립 난수로
만들면 #232 편중이 사라져 A 와 E 가 구분 불가능해진다).

→ 이미 저장된 것에서 되살리는 순서:
**그 실행 자신의 데이터 캐시**(`data_mit.npz` 등)에서 라벨을 찾는다 →
DS2 마스크 길이가 `len(proba)` 와 **정확히** 같을 때만 쓴다 → 안 맞으면
**레코드별 비트 수를 비교**해 원인(레코드 누락 vs 전 구간 소실)을 남기고 잠근다.

⚠️ 이때 `f1`·`macro4` 같은 **저장된 지표는 라벨 없이 회수된다**. 다만 이들은
**동작점(임계값)에 붙어** 있어 Δ 안에 판별력 변화와 임계값 이동이 섞인다 —
AUROC 를 대체하지 못하고, 인용 잠금을 해제하지도 못한다.

## R11. **맥락정의 클래스는 환자를 단위로 채점한다**

실험22-A G1-c 에서 부분과 전체가 반대로 나왔다:

| 코호트 | S 기저율 | PR-AUC Δ | R-prec Δ |
|---|---:|---:|---:|
| 전체 (S 1,808) | 3.78% | **−0.2194** | −0.2094 |
| **#232 만** (S 1,381 = 76%) | 77.63% | **+0.0053** | **+0.0130** |
| #232 제외 (S 427) | 0.93% | −0.0746 미결 | −0.1171 |

**S 의 76% 를 가진 환자 안에서는 오히려 나아졌는데 전역은 무너졌다.**
"전역 S 지표" 는 사실상 **#232 한 명의 지표 + 환자 간 눈금** 이었다.

기전은 상위 목록 구성에서 보인다 — 진짜 S 가 **9·7·0** 개뿐인 #210·#219·#221 이
상위 1,808 슬롯을 **497개** 가져가 다른 환자의 진짜 S 를 밀어냈다.

### 규약

1. **주 지표는 환자 매크로.** 환자별로 재고 평균한다. 전역 풀링은 **보조**다.
2. **최소 양성 수 `GMIN_S`** 를 걸고, 제외된 환자를 **명시**한다(R1 · R7).
3. **지배 지분을 반드시 보고**한다 — `최대 환자 양성 / 전체 양성`.
   이 값이 50% 를 넘으면 **전역 지표를 단독으로 인용하지 않는다.**
4. **환자 간 절대 점수를 비교하지 않는다.** 비교가 필요하면 **환자 내 정규화** 후에.
5. **동작점은 환자별 경보율로 고정**한다 (`colab_step69_ratepoint.py::_t_for_rate`).

### R11-b. **매크로 평균도 지배당한다** — 개체별 값을 전부 보고한다

2026-08-02, 나는 매크로 하나만 보고 "SVDB 증강이 S 를 개선했다" 고 썼다. **틀렸다.**

| 레코드 | S | R-prec Δ |
|---|---:|---:|
| **#213** | 28 | **+0.4857** |
| #232 | 1,381 | +0.0130 |
| #234 · #202 · #100 · #200 · #222 | 50·48·33·30·204 | −0.0040 ~ −0.0294 |

매크로 **+0.0631** 인데 **#213 하나가 +0.0694 를 기여**한다(110%).
#213 을 빼면 **−0.0073** 로 부호가 뒤집힌다. **7개 중 5개는 악화**였다.

레코드 부트스트랩 CI **[−0.0143, +0.2058]** — 0 을 포함한다. 시드 CI 폭의 2.15배.

왜 #213 이 튀나: S 가 28개뿐이라 R-prec 해상도가 `1/28 = 3.6%p` 다. 상위 28개 안에서
13~14개만 달라져도 Δ 가 0.49 가 된다. **작은 n 에서 비율 지표는 폭발한다.**

→ 매크로를 낼 때 항상 **① 개체별 값 전량 ② 최대 기여 개체를 뺀 값 ③ 개체
부트스트랩 CI ④ 개선/악화 개체 수**를 함께 낸다. 평균 하나로는 R10-d 와 **같은
함정**에 빠진다 — 이번엔 풀링이 아니라 매크로가 지배당했다.

→ 그리고 `GMIN_S` 는 지표의 **해상도**를 보고 정한다. R-prec 에 20 은 너무 낮다.

### 어떤 클래스에 거나

정의가 **개인 기준 상대량**인 클래스(S = '평소보다 이르다')는 전역 점수 눈금이
성립할 이유가 없다. 정의가 **내재적 형태**인 클래스(V = '넓은 QRS')는 상대적으로
안전하지만 **면제는 아니다** — 판단 기준은 클래스 이름이 아니라 **지배 지분**이다.
지분을 재고 나서 정한다.

⚠️ 표현(features)과 채점(metric)은 **다른 층위**다. `_medref`·환자상대 리듬특징은
표현 층위의 환자 정규화이고, 위 규약은 채점 층위다. 하나를 했다고 다른 하나가
해결되지 않는다.

## R12. **근사 SE 로 극단값을 판정하지 않는다** — 최대값은 부트스트랩으로만

퀘스트46 Q1 실측. 환자별 AUROC 의 Hanley–McNeil SE 와 부트스트랩 SE 를 대조했다.

| 지점 | Hanley/부트 |
|---|---:|
| **중앙값** | 1.49 ~ 16.07 (Hanley 가 보수적) |
| **최대값** | **0.36 ~ 1.35** (뒤섞임 — 극단에서는 Hanley 가 **과소**) |

중앙에서는 보수적인데 **양성이 3~6개인 레코드에서는 오히려 작게** 나온다. Hanley 의
분산 공식은 이항정규를 가정하는데, 양성이 몇 개뿐이면 부트스트랩이 잡는 '그 몇 개가
안 뽑히는 경우' 를 반영하지 못한다.

**나는 여기서 틀렸다.** 중앙 비 2.76 을 보고 "최대 SE 0.1976 도 2.76 으로 나누면
0.072 라 통과한다" 고 예측했다. 실측 부트 최대는 **0.2661** 로 Hanley 보다 **컸다**.

→ **하나의 배수로 근사를 환산할 수 없다.** 구속 조건이 최대값이면 **부트스트랩으로
직접 잰다**. 근사는 후보를 좁히는 **스크리닝**에만 쓴다.

→ 그리고 검증이 선택에 의존하게 짜지 않는다. Q1 1차 설계는 '근사로 고르고 → 고른
것만 검증' 이라 **근사가 틀리면 검증도 안 돌았다**. 검증이 필요한 바로 그 경우에.

## R13. 지배 지분만으로 **분포가 고른지** 판단하지 않는다

R11-3 은 `최대 개체 양성 / 전체 양성` 을 보라고 했다. 그것만으로는 부족하다.

| 코호트 | 지배 지분 | 양성 > 0 개체 | 중앙값 |
|---|---:|---:|---:|

## R14. **가중치는 개체를 늘리지 않는다** — 유효표본크기를 함께 내고, ESS 가 무너지면 CI 폭을 읽지 않는다

퀘스트46 Q8. Q1 이 남긴 딜레마는 "버리면 12명, 다 받으면 SE 폭발" 이었다. 제3의 길로
**역분산 가중**(`w = 1/SE²`, 메타분석 표준)을 놓고, 픽스처 합성 코호트로 먼저 쟀다.

**① 가중은 개체 수를 늘려주지 않는다.** Kish 유효표본크기 `ESS = (Σw)² / Σw²` 로 잰다.
모두 같은 가중이면 `ESS = n`, 한 개체에 몰리면 `ESS → 1`.

| 합성 코호트 | 개체 | CI 폭(역분산) | CI 폭(단순) | **ESS** |
|---|---:|---:|---:|---:|
| 양성 3,000개 1개 + 12개짜리 26개 | 27 | **0.0206** | 0.0386 | **1.8** |
| 양성 30개 15개 + 90개 15개 | 30 | 0.0214 | 0.0217 | 23.5 |

**② 좁아진 CI 가 정밀도의 증거가 아니다.** 위 첫 줄에서 CI 폭은 **46.6% 좁아졌다.**
폭만 보면 이겼다. 그런데 좁아진 이유는 정밀해져서가 아니라 **가중이 한 개체로
붕괴**해서다 — 사실상 그 한 명의 값을 반복 측정한 것이고, R11-b 의 #213 사고를
가중치로 다시 저지른 것이다. → **관문에 판독 순서를 준다: ESS 관문이 기각이면 CI
폭과 편향 관문은 읽지 않는다.**

**③ 역분산 가중은 SE 가 *참값*일 때만 최적이다.** 우리가 쓰는 SE 는 부트 **추정치**다.
SE 가 코호트 안에서 균질하면 `1/SE²` 는 '우연히 SE 가 작게 나온 개체' 에 가중을
몰아준다 — 순수한 잡음이다. 실측: 25개체가 **전부 같은 조건**일 때 역분산 CI 폭
0.0425 vs 단순 0.0254 — **1.7배 나빴다.** ESS 도 25 → 18.

→ 가중을 쓸 거면 **추정 잡음이 없는 가중**(예: `w = n_pos`)을 나란히 놓고 비교한다.
다만 그게 항상 낫지도 않다: 완만한 이질성에서는 양성수 가중 ESS 24.0 > 역분산 23.5
였지만, 한 개체가 압도하는 코호트에서는 양성수 1.2 < 역분산 1.8 로 뒤집혔다.

**④ 개체 1개짜리는 arm 이 아니다.** 개체가 하나면 개체 부트스트랩이 늘 같은 값을
뽑아 **CI 폭이 0** 으로 나온다. 그걸 기준선으로 쓰면 '폭 0.0000 의 최정밀 기준선' 이
된다(실제로 나눗셈에서 터져서 발견했다). → 매크로 arm 은 **개체 2개 이상**일 때만
성립시키고, 안 서면 관문을 조용히 비우지 말고 **미결**로 남긴다.

### R14-b. 천장이 있는 지표에서 **역분산 가중은 발산한다** — 실데이터가 R14 보다 나빴다

퀘스트46 Q8 실측(INCART · S · `ailab-2026-0050`). 합성 픽스처는 "추정 잡음이 증폭된다"
까지만 잡았는데, 실데이터는 한 단계 더 나쁜 것을 보여줬다.

```
AUROC 는 천장이 1 이다.
개체의 분리가 완벽에 가까우면 → 부트 재표집이 거의 늘 같은 값
                            → 부트 SE → 0
                            → w = 1/SE²  →  ∞
```

**역분산 가중은 '가장 쉬운 개체' 에 무한대 가중을 준다.** 잡음은 방향이 없지만 이건
**천장 쪽으로 편향**된다. 실측 결과:

| 구성 | 개체 | ESS | 최대가중 | 점추정 | CI 폭 |
|---|---:|---:|---:|---:|---:|
| 단순 매크로 (GMIN 10) | 12 | 12.0 | 8.3% | 0.9599 | 0.0330 |
| 양성수 가중 (GMIN 2) | 27 | 5.3 | 30.2% | 0.9510 | 0.0488 |
| **역분산 가중 (GMIN 2)** | 27 | **2.0** | **55.8%** | **1.0000** | 0.0118 |

점추정이 **정확히 1.0000** 이고 CI 가 단순 점추정 0.9599 를 **품지 못했다**. CI 폭은
64.3% 좁아졌다 — R14 ②의 판독 순서가 없었으면 이걸 성과로 썼다.

→ **천장(또는 바닥)이 있는 지표 — AUROC · 정확도 · 민감도 · Dice — 에는 역분산
가중을 쓰지 않는다.** 굳이 쓸 거면 SE 에 바닥을 깔고, 바닥에 걸린 개체 수를 보고한다.

**② `w = n_pos` 도 안전하지 않다.** 정의상 `최대가중 = max(n_pos)/Σn_pos = 지배 지분`
이다. 실측이 그대로 맞았다(30.2% vs INCART 지배 30.1%). 즉 **양성수 가중은 매크로를
전역 지표 쪽으로 되감는다** — R11 이 피하려고 만든 방향이다. 합성 픽스처에서 이게
안전해 보였던 건 거기서 `n_pos` 가 개체마다 같았기 때문이다(= 균등 가중).

**③ SE=0 필터를 전체 arm 에 걸지 않는다.** 0 나눗셈을 막는 `se > 0` 조건을 모든 arm 에
걸면 **완벽 분리 개체를 채점에서 조용히 뺀다** — 가장 쉬운 개체를 빼는 것이라 기준선이
왜곡된다. 필터는 그게 필요한 arm 에만 걸고, 떨어진 개체 수를 로그에 남긴다.

**④ 합성 픽스처에 '완벽 분리 개체' 를 반드시 넣는다.** Q8 픽스처는 분리도를 0.85
근처로 깔아서 AUROC 가 천장에 붙는 개체를 안 만들었다. 그래서 발산을 못 봤다.
경계값이 있는 지표를 검정할 때는 **경계에 붙은 개체**가 시나리오에 있어야 한다.
시나리오를 추가하니 실데이터보다 선명하게 재현됐다 — 완벽 분리 개체 1개 + 보통 개체
20개에서 **그 하나가 가중의 100.0%** 를 가져갔다(ESS 1.00 · 점추정 1.0000). 단순
매크로는 같은 코호트에서 21개체를 전부 유지하고 0.8628 을 낸다.

## R15. 매크로 CI 폭을 만드는 건 **측정오차가 아니라 개체 간 이질성**이다

퀘스트46 Q7-B 실측(SVDB · S · 28레코드 · `ailab-2026-0051`).

| 성분 | CI 폭 |
|---|---:|
| **관측** | **0.0617** |
| 개체 간 이질성만 (개체 AUROC SD 0.0848) | 0.0628 |
| 측정오차만 (RMS SE 0.0228 · 중앙 0.0104) | 0.0169 |

분산비 = **13.8배**. 관측 폭이 이질성 성분과 사실상 같다.

→ **GMIN 을 올려 per-record SE 를 줄여도 매크로 CI 는 거의 안 좁아진다.** 좁히는 건
**개체 수를 늘리는 것**뿐이다.

### ⚠️ R15-a. 단, "개체를 늘리면 좁아진다" 는 **개체 간 동질성을 가정한 문장**이다

Q7-B′ 실측(`ailab-2026-0053`). 개체를 28 → 72 로 **2.6배** 늘렸는데 CI 폭이
**0.0617 → 0.0726 으로 오히려 넓어졌다.**

| | 28개체 | 72개체 |
|---|---:|---:|
| CI 폭 | 0.0617 | **0.0726** |
| 역산 개체간 SD | 0.0833 | **0.1572** (1.89배) |
| √n | — | 1.60배 |
| 이질성/측정오차 분산비 | 13.8 | **49.2** |

새로 들어온 개체 중에 **AUROC 0.0595 짜리**(`#865` — 모델이 역전된 환자)가 있었다.
**SD 가 √n 보다 빨리 자라면 CI 는 넓어진다.** → 개체를 늘릴 때는 **SD 도 같이 보고**
하고, 폭이 안 좁아지면 "표본이 모자라다" 가 아니라 **"새 개체가 다른 분포에서 왔다"**
로 읽는다. Q1 이 '최대 SE ≤ 0.10' 에 매달려 코호트 셋을 기각한 건
필요조건으로서 옳았지만, 정작 Q2 를 가로막는 CI 폭의 **주 원인은 아니었다**.
→ 채점 설계에서 두 가지를 **분리해서** 보고한다: ① per-record SE(그 환자 값을 믿을 수
있나) ② 개체 간 SD(코호트가 얼마나 다양한가). 문턱도 따로 건다.

### R15-b. per-record SE 는 **모델 의존적**이다 — 코호트의 성질이 아니다

같은 실행에서:

| 개체군 | 개수 | 중앙 SE |
|---|---:|---:|
| AUROC ≥ 0.99 | 5 | **0.0010** |
| AUROC < 0.90 | 7 | **0.0153** |

15배 차이다. R14-b 그대로 — AUROC 는 천장이 있어 분리가 좋을수록 부트 SE 가 0 으로
간다.

**★ 바닥 쪽에서도 같다 — SE 관문은 '확신에 찬 오답' 을 못 잡는다.** Q7-B′ 실측:
최대 SE 관문(≤0.10)이 0.0824 로 통과했는데, **가장 망가진 개체 `#865`(AUROC 0.0595 —
역전)의 SE 는 0.0044** 로 실패 목록에서 **가장 촘촘했다.** 모델이 일관되게 틀리면
부트 재표집도 일관되게 틀린 값을 낸다.

→ **정밀도 관문 통과를 성능 근거로 읽지 않는다.** 관문은 「잴 수 있다」는 말이지
「좋다」는 말이 아니다. 성능은 값 자체로 판단하고, 개체별 값을 **전량** 본다(R11-b). 그래서 "SVDB 는 최대 SE 0.0821 로 정밀하다" 는 **"이 코호트 + 이 모델"** 의
성질이지 코호트만의 성질이 아니다. 더 나쁜 arm 을 태우면 같은 코호트에서도 SE 가
커진다. → **SE 관문을 통과한 GMIN 을 다른 arm 에 그대로 물려주지 않는다.** 여유를 둔다.

### R15-c. **반쪽 재현**을 보고한다 — 한 반쪽 통과는 코호트 통과가 아니다

Q7-B 는 SVDB 를 DEV/TEST 로 반씩 갈라 TEST 에서만 채점했다(GMIN 선택 오염 차단, R12).
그 덕에 **같은 DB 의 두 반쪽 값을 나란히 볼 수 있었다**:

| 반쪽 | 개체 | 매크로 | CI 폭 |
|---|---:|---:|---:|
| TEST | 28 | 0.9256 | **0.0617** ✅ |
| DEV | 27 | 0.8382 | **0.1533** ❌ |

개체 수는 거의 같은데 **폭이 2.5배** 다르고, DEV 였다면 CI 폭 관문(≤0.10)이 **기각**
이었다. 분할을 반대로 뒀으면 결론이 뒤집혔다는 뜻이다.

→ 분할을 쓰는 실험은 **반대쪽 반쪽 값도 반드시 같이 낸다.** 두 값이 크게 갈리면
관문 통과는 '이 반쪽에서 통과' 이지 '코호트가 통과' 가 아니다. 확정하려면 전수를
채점해야 한다(선택이 끝난 뒤라면 전수 채점은 정당하다 — 고를 게 더 없다).

### R11-c. '최대기여 개체' 는 **두 정의**가 있고, 관문의 힘은 **n 에 의존**한다

**② 관문의 힘이 n 에 의존한다.** 비가중 매크로에서 개체 하나를 빼면 최대 `|편차|/n`

**사실상 자동 통과**다. R11-b 를 낳은 #213 사건은 **n=7** 이었고 그때 한 개체가 매크로의

**③ 매크로와 부담가중이 갈리면 집계를 갈아타지 말고 상관을 보고한다.** Q7-B 실측:

### R15-d. 문턱 없는 지표를 primary 로 골랐으면 **그 대가를 결론 문장에 쓴다**

Q7-B 는 AUROC 를 primary 로 뒀다. 이유는 타당하다 — 동작점을 테스트에서 고르는 오염을
원천 차단한다. 그런데 07-17 에 전례가 있다:

| 지표 | 대조군 → 실험군 | 판정 |
|---|---|---|
| S ROC-AUC | 0.9223 → 0.9020 (Δ −0.020) | "애매" |
| **S PR-AUC** | **0.5138 → 0.2944 (Δ −0.219)** | **"결정적"** |

ROC 로는 거의 아무 일도 없어 보이는데 PR 로는 반토막이었다. **AUROC 0.926 은 PR-AUC
0.30 과 완벽히 양립한다.**

→ 순위 지표를 primary 로 쓰면 결론 문장에 **"확인한 것은 순위 능력이고 정밀도는
확인하지 않았다"** 를 박고, PR-AUC 를 **탐색적 부지표**로 병기한다(관문 판정은 바꾸지
않는다 — 그건 사후등록이다).

⚠️ PR-AUC 는 **유병률에 붙은 지표**다(R4). 개체마다·코호트마다 유병률이 다르므로
원값을 비교하면 안 된다. **유병률과 우연수준 대비 lift 를 반드시 같이 낸다.**

**Q7-B 실측 — 예측이 틀렸고, 대신 R4 의 교과서적 실례가 나왔다.**
붕괴를 걱정했는데 PR-AUC 매크로는 **0.4978** [0.3973, 0.6031] · lift 30.3배였다.
정밀도도 전이됐다. 그런데 부담군별로 보면:

| 구간 | 개체 | AUROC | 원 PR-AUC | 보유 S |
|---|---:|---:|---:|---:|
| S ≥ 100 | 7 | **0.8765** (최저) | **0.6177** (최고) | 75.8% |
| S < 50 | 17 | 0.9386 | **0.4467** (최저) | 15.2% |

**AUROC 와 원 PR-AUC 가 군 순서를 정반대로 매긴다.**

### ★ 여기서 내가 처방한 교정이 **실측으로 반증됐다**

처음에 "정규화PR `(AP−π)/(1−π)` 과 lift 로 읽으면 된다" 고 썼다. **셋 다 유병률에서
자유롭지 않았다.** 같은 실행을 다시 돌려 열을 붙여 봤다:

| 구간 | AUROC | PR-AUC | 유병률 | lift | **lift 천장(1/π)** | 정규화PR |
|---|---:|---:|---:|---:|---:|---:|
| S ≥ 100 | **0.8765** (최저) | 0.6177 | 0.1404 | 6.6 | **7.1** (92.7% 포화) | **0.552** (최고) |
| 50 ≤ S < 100 | 0.9562 | 0.5052 | 0.0303 | 17.3 | 33.0 | 0.490 |
| S < 50 | 0.9386 | 0.4467 | 0.0120 | 43.2 | 83.3 | 0.441 |

- **정규화PR 은 순서를 못 뒤집었다** — 원 PR 과 같은 순서다. 고정 ROC 에서 `AP ≈ cπ`
  이므로 `정규화PR ≈ π(c−1)` 이고, π→0 이면 **같이 0 으로 간다**. 유병률 무관이 아니다.
- **lift 는 천장이 `1/π`** 다. 부담 큰 군은 천장이 7.1 뿐이고 실측 6.6 — **92.7% 포화**다.
  "lift 가 낮다" 가 아니라 **"더 올라갈 데가 없다"** 이다.
- **lift 를 평균하면 안 된다.** 이 코호트에서 평균 lift 30.3 × 평균 유병률 0.0467
  = **1.42 > 1** 이다. 한 개체에서는 물리적으로 불가능한 값 — 유병률이 다른 개체를
  섞어 평균한 결과다. (노트북이 이 자기검증을 자동으로 찍는다.)

→ **개체·군을 비교하는 지표는 AUROC 뿐이다.** 순위만의 함수라 유병률과 무관하다.
  `AP` 와 `유병률` 은 **그 개체를 서술**하는 데 쓰고, 군 순위를 매기는 데 쓰지 않는다.

### 그럼 두 지표가 반대인 건 무슨 뜻인가 — 모순이 아니다

**부담 큰 레코드는 순위 품질이 나쁜데(AUROC↓) 정밀도는 높다(PR↑).** 양성이 흔하면
어설픈 순위로도 상위권에 진짜가 많이 담긴다. 둘 다 참이고 서로 다른 질문의 답이다.
유병률 17% 인 레코드에서 AUROC 0.7251 은 "순위가 나쁘다" 를, PR 0.3194 는 "그래도
상위권 셋 중 하나는 진짜다" 를 말한다.

→ 보고할 때 **둘 다** 낸다. 단 **비교는 AUROC 로, 서술은 AP+유병률로.**

## R16. **조용한 fallback 은 크래시보다 나쁘다** — 그럴듯하게 틀린 값을 만든다

```python
try:    recs = wfdb.get_record_list("svdb")          # 실제 78개 (빈 번호 있음)
except: recs = [str(i) for i in range(800, 895)]     # 연속 95개  ← 이게 발동했다
num = np.array([int(recs[i]) for i in ridx])         # 인덱스 → 레코드 번호
```

SVDB 는 **813~819·830~839 가 비어 있다**(95개 슬롯에 78개 레코드). fallback 이 걸리면

- 라벨이 정확히 `800~877` 로 찍혔고 그중 **17개는 존재하지 않는 레코드 번호**였다

- 실패 진단 표적으로 지목한 `#853·#868·#872` 는 실제로 **#870·#885·#889** 였다

**터졌으면 즉시 알았다.** fallback 이 그럴듯한 정수를 돌려줬기 때문에 예측·채점·관문·
카드까지 전부 통과했고, 양방향 집합 대조를 하고 나서야 드러났다.

→ **식별자·경로·스키마를 만드는 자리에 fallback 을 두지 않는다.** 못 얻으면 예외.
→ 굳이 둬야 하면 **어느 경로를 탔는지 기록**하고 결과에 표시한다.
→ 그리고 **매핑 결과를 자가검증**한다: 만든 식별자가 원본 목록의 부분집합인가.
   한 줄이면 된다 — `set(num) - set(recs)` 가 비어 있는지.

### R16-b. 집합 대조는 **양방향**으로 한다

첫 감사 셀은 `주석 − 빌드` 만 봤고 결과를 "17레코드 손실" 이라고 이름 붙였다. 같은
출력에 `빌드 성공 78레코드 (100.0%)` 가 찍혀 있었다 — **자기모순**이다. |A|=|B|=78 인데
|A−B|=17 이면 |B−A|=17 이므로 **손실일 수 없다**(손실이면 B ⊆ A 여야 한다).

→ 두 집합을 대조할 때는 **교집합·A−B·B−A 를 전부** 낸다. 한쪽만 보면 '어긋남' 을
'손실' 로 오독하고, 없는 원인(다운로드 실패)을 찾으러 간다.

### R16-c. 복원은 **탐색이 아니라 연역**으로 — 그리고 독립 신호로 검증한다

1차 복원 시도는 S 개수로 그리디 짝짓기를 했다. 결과가 78/78 이었지만 **믿을 수 없다** —
S=0 인 레코드끼리는 아무렇게나 붙고, 실제로 가짜 시프트(9, 42)가 섞여 나왔다.

원인을 알고 나면 복원은 **결정론**이다: `참 번호 = recs[라벨 − 800]`. 그리고 검증은
**독립 신호**로 한다 — S 하나가 아니라 `(N, S, V)` 삼중값을 주석과 대조한다.
실측 확인: 라벨 #868 (예측 S 399) → 참 #885, 주석 S **399** ✓ ·
라벨 #872 (예측 S 152) → 참 #889, 주석 S **152** ✓.
