# 개념 정리본 생성 규칙

정리본은 **학습 목표 단위**의 이론 카드다. 웹 앱(오답 뒤 학습 흐름)과 과별 PDF 학습서가 같은 원본을 쓴다.
계약은 `schemas/frontmatter.md` 의 「개념 정리본(concept)」·「오답 뒤 학습 흐름」 절이 원본이다 — 필드 이름은 거기서 확인한다.

## 무엇을 쓸지는 큐가 정한다(고르지 말 것)

```
python pipelines/concept_queue.py --limit <오늘 상한>
```
- `[note]` — 목표는 있는데 정리본이 없는 오답 → 정리본을 새로 쓴다.
- `[link]` — 목표가 없는 오답 → 문항에 `objective` 를 붙이고, 그 목표의 정리본이 없으면 이어서 쓴다.
- `[touch]` — 목표의 정리본은 **이미 있고**, 새로 틀린 보기만 그 정리본의 `pitfalls[].covers` 에 없다.
  새 정리본을 쓰지 않는다. 기존 혼동 항목으로 설명되면 그 항목의 `covers` 에 `<문항id>:<보기>` 만 더하고,
  아니면 혼동 항목을 하나 추가한다(오답을 일반화해서 — 추측 금지). 본문을 고쳤으면 `version` 을 올리고,
  바꾼 서술만 해리슨으로 대조한다. 정리본이 쌓일수록 대부분의 오답은 이 가벼운 손질이 된다.
- `[root]` — 새로 틀린 **임상** 목표의 정리본에 기초 뿌리(`roots`)도 「없음」(`roots_none`)도 없다 → 아래 「`[root]` — 기초 뿌리」.
  줄 끝에 「상위 20 소급」이 붙은 것은 옛 오답이지만 반복 오답 상위 20개라 예외로 올라온 것이다(2026-11-23) — 처리는 같다.
- 오답은 학습 기록(`state/learning_sync/events.json`)과 **오답 목록(`state/wrong_sync/*.json`)** 두 곳에서 온다(2026-09-23).
  학습 흐름(2026-09-18) 전의 오답은 오답 목록에만 있고, 대개 학습 목표가 없어 `[link]` 로 나온다 — 목표부터 붙인다.
- `[krdiff]` — 정리본 슬롯에 국내 지침 ↔ 해리슨 22판 차이 항목(`content/outline/kr_vs_harrison/`)이 있는데 아직 반영(`kr_diffs`)도
  제외(`kr_diffs_skip`) 표시도 없다(note·link·touch 가 비었을 때만 나온다 · 오답이 걸린 정리본 먼저) → 아래 「국내 vs 해리슨(`[krdiff]`)」.
- `[restyle]` — 판형 2(`note_form: 2`)로 아직 옮기지 않은 옛 정리본(note·link·touch 가 비었을 때만 나온다).
  **새로 쓰지 않고 있는 내용을 판형 2 로 다시 배치**한다 — 아래 「판형 2」 절 · 「판형 2로 옮기기」.
- `[gap]` — 오답과 무관한 기본틀 빈 자리(오답 큐·`[restyle]` 이 비었을 때만 나온다). 이미 단원이 있는 책마다
  「쓴 단원 다음 자리」 하나씩, **정리본이 적은 책이 맨 앞**이다(같으면 기본틀 순서 · 0개인 책과 기초의학 학문별 책은 제외 — 기초 정리본은 `[root]` 에서만, 2026-11-23).
  **맨 앞 줄을 쓴다 — 과를 고르지 않는다.** 하나 쓰면 그 책이 뒤로 물러나 다음 실행은 다른 과가 된다
  (많은 책 먼저였을 때는 한 과만 불었다 — 10월 류마티스 12개 · 11월 순환기 23개).
  **국시 핵심 공백 과목이 앞 묶음이다(2026-11-23 사용자 결정)** — 혈액종양 · 소화기 · 신경 · 감염 · 내분비 · 외과 가운데 정리본이
  12개 미만인 책(줄 끝 「핵심 과목 우선(정리본 N/12)」), 그 안에서도 적은 책부터. 12개가 되면 일반 순서로 내려간다
  (목록 · 기준 수는 `books_config.yaml` `gap_priority`). `[gap]` 으로 새로 쓰는 정리본도 **핵심 변형 문항을 최소 1개** 함께 쓴다
  (`of` 없는 변형 — 그 목표의 결정적 단서를 묻는 문항 하나. 형식은 아래 「`[variant]`」의 보기 · 해설 규칙).
- `[verify]` — 원고에 미대조 표시(`[[?출처]]` · 손으로 적은 `†`)가 남은 정리본(2026-11-23 사용자 결정). **루틴은 처리하지 않는다** —
  PubMed · 지침 원문을 열 수 있는 PC 세션 · Actions 몫이다(`concept_queue.py --verify` 가 목록을 찍는다. 기본 출력에는 건수 한 줄만).
  원문을 열어 확인한 주장은 `?` 를 떼고 그 출처의 `verified` 를 올린다. 확인하지 못한 것은 그대로 둔다.
- 큐가 비어 있으면 **아무것도 만들지 않는다**(학습 기록이 아직 저장소에 없을 때가 대부분 — 정상이다).

## 학습 목표(objective) 정하기

- id 형식 `cn.<과>.<주제>.<목표>` — 소문자·숫자·하이픈. 파일은 `content/concepts/<과 폴더>/<id>.md`.
- **질환명으로 합치지 않는다.** 같은 질환이라도 평가 목표가 다르면 다른 정리본이다
  (예: `cn.derm.pityriasis-versicolor.diagnosis` ≠ `…treatment`).
- 이미 있는 목표로 묶을 수 있으면 새로 만들지 말고 그 문항에 기존 id 를 붙인다(`python pipelines/concept_queue.py` 의
  「이미 정리본이 있는 오답 목표」 수가 그 결과다).
- 문항에는 `objective` 와 함께 가능하면 `distractors`(보기별 tempting·answer_first·discriminator·when_right·split)와
  `case_path`(도식 노드 경로, 문항에 없는 정보는 `state: unknown`)를 적는다 — 형식은 린터가 본다.

## 자리 정하기 — 기본틀 슬롯(`outline`)

정리본은 과별 학습서 안에서 **해리슨 21판의 서술 순서**로 꽂힌다. 그 자리를 frontmatter `outline:` 에 적는다.

```
python pipelines/outline.py --book 순환기내과 --gaps     # 그 과의 빈 자리
python pipelines/outline.py --find "arrhythmia"          # 슬롯·해리슨 장 제목 검색(PDF 를 열지 않는다)
```
- 슬롯 id 는 `h<장번호>`(해리슨이 다루는 주제) 또는 손으로 정한 id(`ob.labor`·`peds.neuro` 처럼 해리슨에 없는 과).
- 한 슬롯에 정리본이 여러 개 있어도 된다(같은 장 안의 다른 학습 목표). 순서만 정해 줄 뿐이다.
- 적을 자리가 마땅치 않으면 `content/outline/subjects.yaml` 에 슬롯을 **추가**한다(해리슨 장은 한 과에만).
- 비워 두면 책 맨 뒤 「배치 대기」로 가고 린터가 WARN 을 낸다.

## 대조 — 해리슨이 기본이다(2026-09-22) · **22판 DB 로 본다(2026-10-31)**

정리본을 다 쓴 뒤 **그 슬롯의 해리슨 22판 장을 읽고** 핵심 서술(기전·기준·치료 선택·금기)을 하나씩 대조한다.
```
python pipelines/outline.py --harrison <슬롯>     # 대조할 22판 장 · 인쇄쪽 · 드라이브 문서 ID · 인용 형식
```
- 슬롯 id(`h<번호>`)는 **21판 장 번호 그대로**다(기본틀 순서의 뼈대). `--harrison` 이 `content/outline/harrison22.json` 의
  대응표로 22판 장(바뀐 번호·나뉜 장)과 드라이브 `교과서/Harrison_22e_장별/H22_<장>` 문서를 알려 준다. 22판에 없는 장
  (21판 7·417·484장)만 21판 문서와 `harrison-21` 로 돌아간다 — 출력이 말하는 판·출처 id 를 그대로 쓴다.
- **클라우드 루틴**: 출력에 드라이브 문서 ID 가 있으면 Google Drive 커넥터 `read_file_content(fileId)` 로 **그 문서만** 읽는다
  (`===== [H22 p.N] =====` 뒤가 인쇄쪽 N). 결과가 커서 「파일로 저장됐다」고 나오면 그 JSON 파일의 `fileContent` 에서 필요한 `[H22 p.N]` 구간만 python 으로 뽑아 읽는다. 원본 PDF 는 읽지 않는다.
- **PC**: 위 드라이브 문서를 읽는다(`harrison_read.py` 는 아직 21판 PDF 전용 — 22판에 없는 장을 볼 때만).
- 해리슨과 맞는 서술에 `[[harrison-22: <22판 장>장 p.<쪽>]]`, 출처에 `harrison-22`(title「Harrison's Principles of Internal Medicine, 22nd ed.」· kind textbook · `verified: text` ·
  `checked` 에 무엇을 몇 쪽에서 확인했는지)을 단다. 해리슨과 **다르면** 고치거나 차이를 본문에 밝힌다(합치지 않는다).
- 해리슨에 없는 서술(지침 세부 수치·최신 약제 등)은 다른 출처로 남기고, 원문을 못 봤으면 `[[?출처]]` 그대로 둔다.
- 드라이브 문서가 없으면 대조하지 않은 채로 둔다 — 린터가 「해리슨 대조 없음」 WARN 을 남기고,
  22판 DB 는 505장 모두 문서가 있다(빠지면 `harrison22_build.py` 로 표를 다시 만든다).
- 이미 `harrison-21` 로 대조한 정리본은 그대로 유효하다 — 일부러 다시 대조하지 않는다. `[touch]`·`[restyle]` 로 서술을 고칠 때
  고친 서술만 22판으로 대조하고 `harrison-22` 출처를 더한다(21판 인용은 지우지 않는다; 22판과 다르면 「시험 쟁점」 새 근거로).
- 해리슨이 다루지 않는 슬롯(산부인과·소아과 손 슬롯 등)은 대조 대상이 아니다(`--harrison` 이 알려 준다).

## `[variant]` — 틀린 문항마다 변형 2개(2026-09-23 사용자 채택)

「오답 → 변형 문항 → 간격을 두고 다시 출제」. 앱은 틀린 날 +1일·+7일(사용자가 바꿀 수 있음)에 「오늘 다시 풀 것」을
띄우고, **그 문항에서 나온 변형**(`of: <문항id>`)을 먼저 낸다. 큐 `[variant]` 는 예정일이 이른 것부터 나온다.
정리본의 `variants` 에 **틀린 문항마다 둘**을 더한다(`version` 올림):
- **A. 단서를 바꿔 답이 바뀌는 변형**(`flip: true`) — 같은 환자 뼈대에서 **결정적 단서 하나**만 바꿔 원래의 혼동 대안이
  정답이 되게 한다. 씨앗은 문항의 `design.switch.condition`(큐의 「씨앗」 칸) → 없으면 `design.discriminator` → 해설.
  예: 「소변검사·크레아티닌 정상」 → 「단백뇨 3+·크레아티닌 2.1」 ⇒ 정답이 항바이러스제에서 스테로이드+리툭시맙으로.
- **B. 겉모습을 바꿔도 답은 그대로인 변형**(`flip: false`) — 나이·성별·내원 경위·검사 이름·제시 순서를 바꾸고 결정적 단서는
  남긴다. 이야기가 아니라 **단서**로 풀었는지 본다.
- 틀린 문항에 `design.trap`(함정 계열, `/gen-kmle` 「함정 계열」)이 있으면 **A 의 씨앗은 그 계열의 반대쪽**이다(큐의 씨앗 칸이
  `design.trap(…)` 으로 나온다) — trap 쪽 문항이면 등록부 `content/traps/<id>.yaml` 의 `mirror.when`(lure 계열이 정답이 되는 조건),
  mirror 쪽 문항이면 trap 쪽 조건(`cue` + `truth`). 등록부 `write_notes` 를 지킨다. 변형은 정리본 `variants` 라 `design.trap` 을 달지 않는다.
- 두 변형 모두 `of: <틀린 문항 id>`, `changed: "<무엇을 바꿨나 → 그래서 답이 어떻게 됐나>"`, `context`(한 줄),
  보기 5개(같은 범주·길이 비슷), `answer`, `explanation`(바뀐 단서가 왜 답을 바꾸는지/왜 안 바꾸는지).
- 형식은 원래 문항의 시험을 따른다 — KMLE 문항이면 한국어 국시형, USMLE 문항이면 영어 USMLE형(`/gen-kmle` 문항 형식).
  원래 발문을 그대로 베끼지 않는다. 새 사실·수치는 정리본 `sources` 로 뒷받침되는 것만.
- `[note]` 로 정리본을 **새로** 쓸 때도 그 목표의 틀린 문항마다 같은 방식으로 변형 둘을 함께 쓴다(다음 실행에 [variant] 로 다시 나오지 않게).

## `[dist]` — 내가 고른 오답 보기의 설명(선지 보정, 2026-09-23)

내가 실제로 고른 오답 보기에 문항의 `distractors.<보기>` 가 없으면 큐에 나온다. **그 문항 파일**(큐의 path — KMLE·USMLE 만,
영상 문항은 빌더 파생물이라 제외)에 그 보기 하나의 설명을 더하고 문항 `version` 을 올린다:
`tempting`(이 보기가 왜 그럴듯한가 — 보기 자체의 이유, **학습자의 속마음을 추측하지 않는다**) · `answer_first`(왜 정답이 먼저인가) ·
`discriminator`(둘을 가르는 소견 — 문항 안의 정보로) · `when_right`(이 보기가 정답이 되는 조건, 있으면).
해설과 모순되면 해설을 고치지 말고 보고에 남긴다(문항 내용 변경은 사람 검토).

## `[root]` — 기초 뿌리(2026-11-21 사용자 결정)

임상 정리본은 「무엇을 고르나」(판단)를, 기초 정리본은 그 밑의 「왜 그런가」(정상 → 고장 → 소견)를 쓴다. 기초 정리본은
**학문별 책**(생리학 · 병리학 · 약리학 · 생화학·유전 · 미생물학 · 면역학 · 해부·조직·발생)에 따로 쌓이고, 임상 정리본이 `roots` 로 가리킨다.

큐 `[root]` = 새로 틀린 임상 목표인데 그 정리본에 `roots` 도 `roots_none` 도 없다. 한 줄마다 셋 중 하나로 끝낸다.
1. **있는 것에 잇는다** — `python pipelines/concepts.py --basic` 목록에 같은 기전의 기초 정리본이 있으면 새로 쓰지 않고
   임상 정리본에 `roots: [<기초 id>]` 만 단다. 기초 정리본은 **기전 단위**다(사구체 혈역학 하나가 ACE억제제 급성신손상 · NSAID
   신손상 · 신동맥협착을 모두 받친다) — 문항마다 하나씩 만들지 않는다. 뿌리는 보통 1개, 많아야 2개.
2. **새로 쓴다** — 없으면 기초 정리본을 쓰고(아래 모양) 임상 정리본에 `roots` 를 단다.
3. **없음** — 기초 기전으로 내려가지 않는 목표(검진 주기 · 의료법규 · 역학 계산 · 지침의 수치 기준 · 순수한 분류 암기)는
   `roots_none: "<이유 한 줄>"`. 억지로 만들지 않는다.

- 임상 정리본에는 `roots`/`roots_none` 한 줄만 더한다 — 본문을 고치지 않으므로 `version` 은 올리지 않는다(`updated` 만 오늘로).
- `[note]` 로 임상 정리본을 **새로** 쓸 때도 같은 판단을 함께 해 `roots`/`roots_none` 을 남긴다(다음 실행에 [root] 로 다시 안 나오게).
  뿌리가 있으면 그 임상 정리본의 `## 기전` 절은 2~3줄(이 판단에 필요한 고리만)로 줄이고 나머지는 기초 정리본에 둔다 —
  같은 설명을 두 책에 쓰지 않는다.
- **소급하지 않는다** — 큐는 2026-11-21 이후에 틀린 목표만 낸다(`concept_queue.ROOTS_FROM`). 옛 정리본에 일부러 뿌리를 달지 않는다.
  **예외(2026-11-23 사용자 결정)**: 반복 오답 상위 20개 임상 정리본(2회 이상 틀린 것 · 오답 수 → 우선순위 → id)은 옛 오답이라도
  큐가 「상위 20 소급」으로 올린다. 상위 20 은 뿌리가 붙었는지와 무관하게 뽑혀 그 20개에서 끝난다 — 큐에 없는 옛 정리본은 건드리지 않는다.

기초 정리본의 모양
- id `cn.<학문 약자>.<기전 주제>.<목표>`(physio · path · pharm · biochem · genetics · micro · immuno · anat · histo · embryo),
  파일은 `content/concepts/<학문 폴더>/`. `topic` 은 학문 이름(Physiology · Pathology · Pharmacology · Biochemistry · Genetics ·
  Microbiology · Immunology · Anatomy · Histology · Embryology) — 그래야 학문별 책으로 간다(린터가 본다).
- frontmatter: `layer: basic` · `discipline: <학문>` · `system: <장기계통>`(목록은 린터 오류가 알려 준다) · `objective_kind: 기전` ·
  `outline: <학문별 책 슬롯>`(`python pipelines/outline.py --book 생리학`) · `textbook_check`.
- `textbook_check` — `checked`(전공 교과서 본문과 대조: 출처 kind textbook · verified text) · `pending`(그 학문 교과서가
  `books_config.yaml` 의 `textbooks` 에 있으나 아직 읽을 수 없다 — 지금은 병리 · 약리 · 조직 · 생리) · `unavailable`(등록된 교과서가
  없다 — 생화학 · 유전 · 미생물 · 면역 · 해부 · 발생). pending · unavailable 이면 **해리슨 22판**의 기전 서술로 대조한다
  (`python pipelines/harrison_cite.py --find <주제>` → `--chapter <장>` 이 준 드라이브 문서, 인용 `[[harrison-22: <장>장 p.<쪽>]]`).
  학습서에는 그 단원 머리에 「전공 교과서 미대조」가 붙는다.
- 본문 절: `## 정상 — <구조·조절>` → `## 고장 — <어디가 어떻게 깨지나>` → `## 소견으로 — <검사·증상이 생기는 이유>` →
  `## 임상 판단으로 — <이 기전이 가르는 선택>`(받치는 임상 판단을 2~4줄로 — 치료 수치·권고는 임상 정리본에 둔다) →
  `## 시험 쟁점 — 충돌·맥락·새 근거`. 판형 2 예산(summary 머리말 · title ≤ 40자)은 그대로. 도식은 기전 목표라 생략해도 된다.
- 기초 정리본에는 `roots`·`roots_none` 을 달지 않는다. `exams` 는 보통 `[usmle, kmle]`.
- **최근 근거(논문)는 루틴이 찾지 않는다**(PubMed 가 막혀 있다). 교과서 서술이 낡았다고 보이면(해리슨 22판과 어긋남 · 분자병리 ·
  면역 · 신약 기전) 보고에 「최근 근거 필요: <정리본 id> — <무엇이>」로 남긴다 — PC 세션이 PMID 가 확인된 최근 10년 종설 ·
  합의문으로 `## 최근 근거` 절을 채운다. 시험 답은 교과서 기준으로 두고, 어긋나는 곳은 「시험 쟁점」의 새 근거로 적는다.

임상 책에 실린 정리본이 기초 학문 성격이면(조직 소견 · 약물 상호작용 기전처럼) `discipline: <학문>` 꼬리표만 단다 — 본문은 그 임상 책에
그대로 있고, 학문별 책의 목차 쪽 「다른 책에 실린 단원」에 제목이 적힌다.

## 국내 vs 해리슨(`[krdiff]`) — 국시 기준과 USMLE 기준을 갈라 적는다(2026-11-25 사용자 결정)

사용자 지시: 「옛 정리본 · 복습용 학습서에도 국내 · 미국 기준을 구분해서 넣고, 아직 정리되지 않은 정리본은 이걸 확인해서 만든다」.
원본은 과별 대조 파일 `content/outline/kr_vs_harrison/<과>.yaml` — 항목마다 국내 지침 원문 쪽(`kr_cite`) · 해리슨 22판 쪽(`h22_cite`) ·
`kr_says` · `harrison_says` · `kmle_rule` · `usmle_rule` 이 있다. 지침 서지(doi · pmid · 누리집)는 `content/outline/kr_guidelines.json`.
**새로 대조하지 않는다** — 이 파일에 없는 차이를 기억으로 만들지 않는다(대조 파일을 늘리는 일은 PC 세션 `kr_guidelines.py --batch <과>`).

- **언제** — 큐 `[krdiff]` 한 줄 = 정리본 하나. 그리고 `[note]` · `[gap]` 으로 **새로** 쓰거나 `[restyle]` · `[touch]` 로 손보는 정리본도
  `python pipelines/concept_queue.py --json` 의 `krdiff` 에 그 id 가 있으면 같은 처리를 함께 한다(다음 실행에 다시 안 나오게).
- **항목마다 하나로 끝낸다** — 줄에 적힌 항목(`items`)을 대조 파일에서 읽고
  - 이 정리본의 학습 목표 · 본문이 닿는 차이 → **넣고** frontmatter `kr_diffs` 에 id 를 더한다.
  - 같은 슬롯이지만 이 목표와 무관(예: 항응고 정리본에 율동전환 시간 항목) → `kr_diffs_skip` 에 id 를 더한다. 둘에 함께 두지 않는다.
- **넣는 자리**
  - `## 시험 쟁점 — 충돌·맥락·새 근거` 에 **맥락** 항목 하나(네 칸 그대로): `시험 기준:` = `kmle_rule` 의 국내 기준 + `[[<국내 출처 id>: p.N]]` /
    `다른 기준:` = `harrison_says` 의 해리슨 22판 기준 + `[[harrison-22: N장 p.N]]` / `왜 다른가:` = `kr_says` · `harrison_says` 에 적힌 까닭(국내 내성률 ·
    발생률 · 급여 기준 · 근거 시험 — 대조 파일에 없으면 「대조 파일에 적힌 까닭 없음」) / `시험에서는: KMLE … · USMLE …`(`kmle_rule` · `usmle_rule`).
  - 본문 · `criteria` · 표가 그 기준을 **수치로** 말하고 있으면 그 줄을 국내 기준으로 고치고 해리슨 값은 쟁점 카드로 옮긴다. 해리슨만 인용해 쓴
    문장을 지우지 말고 「해리슨은 …」으로 남긴다(앞 판의 대조 기록이다).
  - 쟁점이 아닌 출제 맥락(국내만 있는 제도 · 급여 · 국내 미도입 약)은 `exam_points: {kmle: "…", usmle: "…"}` 한 줄씩.
  - 학습서(PDF)와 앱은 이 칸들을 그대로 그린다(판형 12 — 쟁점 카드 · 「KMLE / USMLE 포인트」). 따로 상자를 만들지 않는다.
- **출처** — 국내 지침을 `sources` 에 하나 더한다: `kind: guideline` · `citation`(레지스트리 `title` · `journal`) · `doi` · `pmid`(있으면) 또는 `url`
  (doi 가 없으면 `https://` + `source_portal`). `checked` 에 「kr_vs_harrison <항목 id> 의 원문 대조(쪽)에서 옮김」, `verified: citation`
  (이 정리본을 쓰면서 드라이브 `_가이드라인` PDF 그 쪽을 직접 읽었으면 `text`). 항목이 `verified: pending` 이면 시험 기준으로 쓰지 않는다 —
  쟁점 카드의 「다른 기준」에 `[[?<출처 id>]]` 로만, 또는 `kr_diffs_skip`.
- **문항은 고치지 않는다** — 정리본을 국내 기준으로 바꿔 기존 문항의 해설 · 정답과 어긋나면 보고에 「문항 수정 후보(문항 id · 줄 · 국내 기준 · 쪽)」로만
  남긴다(문항 본문 수정은 사용자 승인 뒤).
- 검증: `python pipelines/kr_guidelines.py --check`(적은 id 가 대조 파일에 있는가) + 평소의 `concepts.py`.

## `[figure]` — 정리본 그림(심전도·조직·영상 사진, 2026-09-27 사용자 요청)

그림은 소견을 **보여 줘야** 이해되는 목표에만 싣는다. 사용자 조건 두 가지가 규칙의 뼈대다.
1. **확실한 라벨만** — ① 전문가가 판정한 데이터셋 라벨(데이터 논문이 있고 여러 연구가 쓴 것: PTB-XL·ISIC 조직확진·IDRiD·
   FracAtlas·GRAZPEDWRI·AML 형태·태아 표준 단면·HPA) 또는 ② 동료 심사 논문(PMC 오픈액세스, CC BY)의 그림 설명이 그 소견이라고
   말하는 그림. **모델이 그림을 보고 붙인 판독은 라벨이 아니다.** 슬라이스 단위 라벨이 없는 CT·MRI(LIDC·TCIA 코호트)와
   작성자가 읽은 태아심박동(CTU)은 쓰지 않는다(`concept_figures.py find --all` 이 이유를 보여 준다).
2. **이미 모아 둔 풀에서 고른다**(exam-builder `open_assets` — 틀린 영상 문항의 그림도 여기서 왔다). 없으면 요청을 남기고,
   exam-builder 아침 수확(`opendata demand`, 하루 6건)이 받아 온다.

큐 `[figure]` 세 갈래(이 순서):
- **question** — 이 목표의 영상 문항 그림이 기준을 통과한다. 그림 파일(`../exam-builder/open_assets/<file>`)을 **열어 보고** 붙인다.
- **attach** — 요청한 그림이 풀에 들어왔다. 열어 보고 ① 요청한 소견이 그림 설명(라벨)과 그림에 실제로 있는지 ② 얼굴·문신·이름·
  병원 표지가 없는지 확인한다. 맞으면 `add … --privacy-checked "<무엇을 확인했나>"`(여러 패널이면 `--crop x0,y0,x1,y1` 로 한 패널),
  아니면 `reject <정리본> <자산> "<이유>"` — 수확이 다음 후보를 받는다.
- **assess** — 아직 판단 안 한 정리본. `find <영어 소견 말>` 로 풀 후보를 찾아 `add`, 없으면 `want`, 영상 소견이 시험 단서가
  아닌 목표(수치·순서·약물 선택·기전)는 `none "<이유>"`. **얼굴 사진이 대표 소견인 주제는 싣지 않는다**(none 에 그 이유).
```
python pipelines/concept_figures.py find flutter AFLT
python pipelines/concept_figures.py add <정리본> <자산> --at "<## 절 제목>" --shows "<보여 주는 소견 한 줄>" --look "<보는 곳>" --look "<보는 곳>"
python pipelines/concept_figures.py want <정리본> --source PTBXL --codes AFLT --shows "…"          # 데이터셋 — 코드로 받는다
python pipelines/concept_figures.py want <정리본> --source PMC_OA --query '"hyperkalemia" AND "peaked T" AND "case report"' \
       --caption-terms "peaked" --modality ECG --shows "…"                                         # 논문 그림 — 설명에 이 말이 모두 있어야
python pipelines/concept_figures.py none <정리본> "<그림이 필요 없는 이유>"
```
- **라벨·근거·데이터 논문·출처·라이선스는 스크립트가 풀 기록에서 채운다** — 손으로 쓰지 않는다. `shows` 는 **라벨이 말하는 범위 안에서만**
  (라벨이 「엉덩관절 골절」이면 「경부 골절」이라고 쓰지 않는다 — 그 구분이 목표면 그 그림은 거절하고 더 구체적인 것을 요청).
  `look_for` 는 그림에서 **실제로 보이는 것**만 1~3개. 이 설명은 검토 전으로 표시된다.
- `at` 은 본문 `## 절` 제목 그대로 — 보통 「기전에서 소견으로」나 소견을 설명하는 절. 한 정리본에 그림은 3개까지.
- 새 정리본(`[note]`)을 쓸 때도 같은 판단을 해 `figures`·`figures_wanted`·`figures_none` 중 하나를 남긴다(다음 실행에 assess 로 다시 안 나오게).
- 학습서: 사진은 한 단 안 「그림 왼쪽·설명 오른쪽」(최대 78×66 mm), 심전도·태아심박동은 두 단 전체. 캡션 = [그림] 소견 · 보는 곳 ·
  데이터 라벨 · 라벨 근거와 데이터 논문(피인용 수) · 출처·라이선스. 앱은 그림을 먼저 보여 주고 「소견 보기」로 연다(인출).

## 시험 쟁점 절 — 시험 답이 갈릴 수 있는 곳은 따로 모은다(2026-09-23)

사용자 지시: 충돌 지점 · 맥락 차이 · 새 연구로 논란인 내용은 본문에 섞지 말고 따로 뺀다. 학교 정리본(의대_정리본_제작 CLAUDE.md
「시험 쟁점 부록 규칙」)과 같은 규칙이다. 본문 · `criteria` 는 **시험 답으로 쓸 기준 하나**로 쓰고, 갈리는 곳은
`## 권고와 예외` 다음 · `(심화)` 앞의 `## 시험 쟁점 — 충돌·맥락·새 근거` 절에 모은다.
- 종류 — **충돌**(같은 질문에 자료마다 답이 다르다) · **맥락**(대상 · 정의 · 나라 · 시점이 달라 숫자가 다르다: 한국 vs 미국, KMLE vs USMLE) ·
  **새 근거**(해리슨 22판 · 지침 판 이후 개정 · 새 약 · 새 시험).
- 한 항목 = 글머리 하나, 네 칸 고정:
  `- **Z1 충돌 · <제목>** — 시험 기준: … [[출처]] / 다른 기준: … [[출처: 쪽]] / 왜 다른가: … / 시험에서는: KMLE … · USMLE …`
- 「다른 기준」도 **읽은 것만** 쓴다 — 기억으로 「옛 지침은 …」이라고 쓰지 않는다(원문 못 봤으면 `[[?출처]]`).
- 해리슨과 대조해 어긋난 곳이 없으면 절에 한 줄: `- 해당 없음(대조: 해리슨 N장 p.#~#)`. 대조하지 못했으면 절을 두지 않는다(린터의 「해리슨 대조 없음」 WARN 이 남는다).
- `[touch]` 로 손볼 때 이 절이 없는 옛 정리본이면, 바꾼 서술을 대조하면서 함께 만든다.

## 해리슨을 읽어야 할 때 — 그 장만 읽는다

기본은 위 `--harrison` 이 준 22판 드라이브 문서 하나다. 아래 `harrison_read.py` 는 PC 의 **21판 PDF** 용이다.
```
python pipelines/harrison_read.py --slot h255                 # 그 슬롯의 장 전체(기본 12,000자)
python pipelines/harrison_read.py --chapter 255 --grep "QT"   # 그 장에서 맞는 줄만
python pipelines/harrison_read.py --chapter 255 --pages 1925  # 인쇄쪽으로 더 좁히기
```
교과서를 통째로 뒤지지 않는다. 읽은 쪽은 `[[harrison-22: 262장 p.<읽은 인쇄쪽>]]`(21판 255장 → 22판 262장 · 21판으로 읽었으면 `[[harrison-21: 255장 p.1925]]`) 처럼 인용하고
`sources[].verified: text` 로 올린다(본문을 저장소 파일로 저장하지 않는다 — 교과서 저작권).

## 근거 — 확인한 것만

- 본문·표·혼동 항목의 수치와 권고에는 `[[출처id: 쪽·절·표]]` 로 위치를 단다.
- `sources[].verified` 는 실제로 어디까지 봤는지다: `text`(권고 본문 대조) · `abstract`(초록만) · `citation`(서지만).
  text 가 아니면 화면·PDF 에 † 가 붙는다. 원문을 못 본 주장은 `[[?출처id]]`.
- **해리슨 22판에 이미 있는 내용에는 습관처럼 출처를 덧붙이지 않는다(2026-11-23 사용자 결정).** 해리슨으로 대조한 서술은
  `[[harrison-22: <장>장 p.<쪽>]]` 하나면 된다 — 열어 보지 못한 지침 · 논문을 `verified: citation`(서지만) 출처와 `[[?출처id]]` 로
  나란히 달면 미대조 표시만 늘어 `[verify]` 에 쌓인다. 다른 출처는 해리슨에 없는 서술(지침 세부 수치 · 최신 약제)과 「시험 쟁점」에만.
- 교과서는 `G:\내 드라이브\교과서\` 의 Harrison(인쇄쪽 = PDF 인덱스 − 40)·Guyton(스캔본, 렌더해서 읽기)을 인용할 수 있다.
  논문·지침은 PubMed·기관 쪽에서 **실제로 열어 본 뒤** 서지와 쪽수를 적는다. 없는 출처·안 본 쪽수를 만들지 않는다.
- 논문·지침에는 **`pmid` 를 붙인다**(DOI 만 두지 않는다 — 개정·철회 추적은 PMID 로 한다). 컨테이너가 PubMed 를 막아
  PMID 를 못 찾으면 DOI 만 두어도 된다(학습서 워크플로가 DOI 로 PMID 를 찾아 본다). 기억으로 적은 DOI 는 `checked` 에 그렇게 쓴다.
- 다른 나라·기관의 기준은 `criteria` 행을 나눠 쓰고 설명 없이 합치지 않는다(KMLE/USMLE 는 `exams` 로 구분).
- `review_status: unreviewed` 로 둔다. 사람이 본 뒤에만 `reviewed`+`reviewed_by`+`review_note`.

## 도식

`decision_diagram.py` 규격: 세로, 판단 노드는 갈래 2개 이상·조건 라벨 필수, 「추가 정보 필요(info)」 노드 1개 이상,

`python pipelines/concepts.py` 가 **ERROR** 로 막는다(2026-09-24 대동맥 박리 도식 하나가 그날 모든 학습서를 멈췄다).
안 들어가면 노드 글부터 줄이고(판단 ≤ 30자), 그래도 층이 9개를 넘으면 단계를 합치거나 의미 단위로 나눈다.
배치(선·라벨 위치)는 코드가 정한다 — 노드 순서·선 모양을 글로 맞추려 하지 않는다.
학습서는 노드 글을 **항목 경계**(쉼표 뒤, → + — ± 앞, 가운뎃점·닫는 괄호 뒤)에서만 줄바꿈한다(`dd.phrase_wrap`) —
한 항목이 길면(괄호 안 나열 등) 그대로 한 줄을 차지하니, 노드 글은 항목을 「·」「,」「→」로 끊어 쓴다.
