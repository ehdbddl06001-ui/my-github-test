# OncoReg Studio — 자유서술/PICO 검색 · 유사도 가중 · 문서 스튜디오

기존 `oncoreg-ai`(드롭다운)를 전면 재설계한 새 모듈. **Gemini 또는 OpenAI 자동감지**로 구동
(`GEMINI_API_KEY` 있으면 Gemini, 없고 `OPENAI_API_KEY` 있으면 OpenAI. `LLM_PROVIDER`로 강제 가능).

## 5개 탭
- **① 자유서술 검색** — 상황을 줄글로 적으면 LLM이 해석해 PICO 요약 + 관련도순 논문/증례.
- **② PICO·약제 검색** — 약제(예시 20종)를 고르고 P·I·C·O 단답으로 근거 검색(①과 같은 랭킹).
- **③ 문서 스튜디오** — 오른쪽 **실제 별지 제1호서식**, 왼쪽에서 칸별 근거를 골라 채움 + 검증·저장.
- **④ 임상시험 연결(expanded access)** — 표준치료 소진 환자의 진행 중 임상시험을 LLM으로 검색.
- **⑤ 사후결과 보고서** — ③에서 저장한 신청서를 **별지 제3호서식**으로 연동, 결과만 추가 작성.

## 무엇이 달라졌나
1. **자유 서술(챗) + PICO·약제 단답형** — 전형 케이스는 P·I·C·O 단답, 특이 케이스는 자유 서술.
   LLM이 조건을 해석하고 결과 상단에 PICO 요약을 보여준다.
2. **관련도는 모델이 판단** — 유사도 5축(**증상·나이·기저질환·병리·기존 투약**) 상세와 함께
   **가이드라인이 아니라 논문/증례**를 관련도순으로(원저 절반·증례 절반). `다시 검색`으로 변주.
3. **왜 적합한지 상세히** — 논문마다 5축 점수 + 축별 근거(sim_detail) + `왜 적합한가` 설명.
4. **논문 URL** — 각 논문에 PubMed·Google Scholar 검색 링크(제목 기반)와 DOI(있으면).
5. **선택은 사용자가** — 처음엔 아무 논문도 선택되지 않고, `사용` 체크로 직접 고른다.
6. **가이드라인 기준치 박스(한/미/유럽)** — 스튜디오 상단에 핵심 지표의 한/미/유럽 기준치 표 +
   각국 가이드라인 바로가기. 용법·용량 등 칸에는 AI 자동초안 위에 한/미/유럽 링크가 고정 노출.
7. **한국 기준 위반 값 차단** — 논문 수치가 한국 기준을 벗어나면(⛔) **빨간색·클릭 불가**로 표시되고
   AI 자동채움에서도 제외된다.
8. **근거 출처 표시** — 채운 칸마다 어느 논문에서 왔는지 **아주 작은 제목**이 붙는다(칸 아래·서식 안).
9. **초안 검증 파이프라인** — `초안 오류 검증`으로 사실 불일치·한국 기준 위반·누락을 점검.
10. **문서 스튜디오** — 서식 칸을 클릭(활성화)하고 근거를 누르면 `값 — "원문 한 문장" (출처, 위치)
    [번호]` 형태로 삽입되고, 인용 원문이 하이라이트로 표시된다. 문서 자동 서술 없이 **선택으로만**.

```
[자유서술/PICO·약제] --LLM--> [관련도 랭킹·선택] --> [스튜디오: 좌 근거삽입·검증 / 우 실제 서식] --저장--> [사후결과 보고서]
                                                 └--> [임상시험 연결(expanded access)]
```

## 실행 — Colab (권장)
1. OpenAI 키 발급: <https://platform.openai.com/api-keys>
2. Colab → 파일 → 노트북 업로드 → `OncoReg_Studio_Colab.ipynb`
3. 셀 순서대로: ⓪초기화 → ①설치 → ②파일 기록 → ③**키 입력 칸**에 붙여넣기 → ④**서버 실행**
4. 출력된 `trycloudflare.com` 주소를 새 탭에서 열기.

## 실행 — 로컬
```bash
cd prototypes/oncoreg-studio
pip install -r requirements.txt
export OPENAI_API_KEY="sk-..."          # Windows(PS): $env:OPENAI_API_KEY="sk-..."
export OPENAI_MODEL="gpt-4o-mini"       # 선택
python server.py                         # http://localhost:8000
```
## 모델 · 속도 (중요)
느리게 느껴지면 **Pro가 아니라 더 가벼운 Flash로 내려야** 빨라집니다(Pro는 품질↑·속도↓).
- **빠름**: `gemini-2.5-flash-lite`, `gemini-2.0-flash`
- **균형(기본)**: `gemini-2.5-flash`
- **고품질·의학 추론(느림)**: `gemini-2.5-pro`

가장 큰 속도 요인은 모델보다 **① 2.5-flash의 기본 '사고(thinking)'** 와 **② 큰 출력(논문 6~8편)** 입니다.
- 서버는 flash 계열에서 `GEMINI_THINKING=0`(사고 끔)으로 **기본 빠르게** 돕니다.
- 품질을 더 원하면 `GEMINI_THINKING=512`(예) 로 올리거나 `GEMINI_MODEL=gemini-2.5-pro`.
- 모델 변경: 노트북 3번 셀의 Model 칸, 또는 로컬에서 `export GEMINI_MODEL=...`.

> OpenAI로 쓸 경우 모델은 `gpt-4o-mini`(빠름/저렴) / `gpt-4o`(고품질). 비용은 각 공급자 요금 페이지 참고.
> 무료 크레딧/결제 미설정 시 401/429가 날 수 있음 — 키·크레딧 확인.

## 쓰는 법 (시연 순서)
1. **① 자유서술 검색**: 상황을 줄글로 적고 검색 → 해석 요약(PICO) + 근거수준 배지가 달린
   논문/증례가 관련도순으로. 맨 위 = ‘최적’. `사용` 체크로 쓸 논문을 직접 고른다(기본 미선택).
2. **② PICO·약제 검색**: 약제(예시 20종)를 고르고 P·I·C·O 단답으로 검색 → 같은 랭킹 화면.
3. **③ 문서 스튜디오**: ‘선택한 논문으로 서류 작성 →’ → 오른쪽 실제 서식, 상단 한/미/유럽 기준치 박스,
   왼쪽에서 칸별 근거를 눌러 삽입(⛔ 한국 기준 위반 값은 클릭 불가). `초안 오류 검증`으로 점검하고
   `신청서 저장`으로 ⑤와 연동. 체크(유형/희귀/병용/질환유형)·주성분명도 좌측에서 조정. 인쇄/PDF.
4. **④ 임상시험 연결**: 표준치료 소진 환자 상황을 적으면 진행 중 임상시험 후보(등록번호·모집상태·링크).
5. **⑤ 사후결과 보고서**: `저장된 신청서 불러오기` → 별지 제3호서식에 기관·주성분·근거가 연동되고
   치료기간·결과·이상반응만 추가 작성. 인쇄/PDF.

정적 호스팅(GitHub Pages 등)에서 열면 상단 **엔진 배지 클릭 → Colab 백엔드 URL** 을 넣어 라이브로 붙일 수 있고, 넣지 않으면 **데모 데이터**로 UI 전체가 동작한다.

## 백엔드 프레임만 실제 서식이고 나머지는?
서식(별지 제1호)은 실제 HWP 좌표로 재현. 검색·지정·가이드라인은 LLM 생성이므로 **참고용**이며,
실데이터가 필요하면 `/api/search`를 PubMed/식약처·심평원 공고/ClinicalTrials.gov 등으로 교체하면 된다.
